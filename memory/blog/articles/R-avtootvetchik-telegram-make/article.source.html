Ниже – свой бот и три кубика в Make (визуальный конструктор сценариев без кода): входящее → фильтр → один шаблонный ответ. Без подписки Premium и без Python. Открытый вопрос: почему после «быстрой» сборки бот иногда спамит сам себе и жжёт операции вместо одного спокойного ответа?

MVP автоответчика: бот из @BotFather плюс сценарий Make из трёх кубиков – слушает входящие, отсекает мусор и свои же сообщения, шлёт один шаблонный ответ. Задача – мгновенная реакция, чтобы заявка не висела в тишине. Проверка: со второго аккаунта написали боту – пришёл ровно один заранее заданный текст, сценарий включён.

Это не статичная отбивка Premium и не запись строки в Google Sheets. Сначала ответ клиенту в личке бота. Таблица и ИИ – соседние шаги, когда базовый автоответ уже спокойный.

Создайте бота в @BotFather и спрячьте токен

Без бота Make некуда стучаться. Откройте в Telegram @BotFather и сделайте нового бота по шагам:

  1. Шаг 1. Отправьте /newbot, задайте имя и username.
  2. Шаг 2. Скопируйте token (длинный ключ доступа) в менеджер паролей.
  3. Шаг 3. Не публикуйте токен в чат клиенту и не кладите в открытый репозиторий: у кого ключ – полный контроль над ботом.
  4. Шаг 4. Напишите боту /start со своего аккаунта – бот не начинает диалог первым.
  5. Шаг 5. Оставьте окно @BotFather закрытым: дальше работа в Make.
  6. Шаг 6. Если бот уже был – не создавайте второго «на всякий случай»; один бот – один токен – один триггер.

На практике новичок теряет вечер, когда токен «светится» в пересылке коллеге. Уберите его из публичных заметок до первого теста.

Прогресс: бот создан, токен только у вас.

Почему бот «слышит сам себя» – до кнопок в Make

Типичная ошибка: собрали «слушает входящие → сразу ответ», включили сценарий – и бот начал спамить сам себе. Каждое его сообщение снова запускало цепочку. В community Make это частый сюжет: не «баг Telegram», а петля.

Watch Updates (модуль «слушает входящие») – это триггер: новое сообщение у бота → сценарий стартует. Send a Text Message or a Reply (отправка текста клиенту) – это модуль ответа. Но триггер видит и собственные ответы бота. Без Filter (правило «идти дальше только если…») на линии получается петля: услышал → ответил → снова услышал.

Простыми словами: бот слышит сам себя, как микрофон у колонки. Лечится не отключением бота, а фильтром «текст есть» и «сообщение не от бота». webhook (ссылка-розетка для мгновенных апдейтов) – это способ доставки входящих в Make: один триггер на одного бота; два Watch Updates на одного бота часто ломают приём.

Прогресс: понятно, зачем фильтр стоит до ответа, а не «потом как-нибудь».

Соберите цепочку в Make: три модуля и антипетля

workflow (порядок шагов) – это цепочка модулей в Make, которую диспетчер прогоняет на каждое входящее. Откройте Telegram в Make и соберите MVP:

  1. Шаг 1. Сделайте New scenario → Telegram Bot → Watch Updates → Add connection → вставьте token.
  2. Шаг 2. Добавьте Filter на линии после триггера: Message Text Exists (текст есть).
  3. Шаг 3. В том же Filter исключите сообщения от бота (From.is_bot / свой bot id) – иначе петля вернётся.
  4. Шаг 4. Используйте Send a Text Message or a Reply: Chat ID из Watch Updates; текст вроде «Спасибо! Мы на связи 10:00–19:00. Опишите задачу одним сообщением – ответим лично».
  5. Шаг 5. Не плодите второй Watch Updates: ветки FAQ или «уведомить себя» – через Router (развилка веток) позже.
  6. Шаг 6. Избегайте сразу ChatGPT: сначала один шаблонный абзац. ИИ-чат – отдельный гайд ИИ-чат-бот для бизнеса.
  7. Шаг 7. Сохраните сценарий с понятным именем, например «TG автоответ MVP», чтобы не перепутать с черновиками.

Цепочка коротко: Watch Updates → Filter → Reply. Документация фильтров – help.make.com/filters. Если позже понадобится HTTP-ветка – HTTP в Make; для Telegram-модулей берите apps.make.com, не чужие зеркала.

Например, стикер без текста не должен жечь операции: Filter «текст есть» отсекает пустые апдейты. В реальном проекте часто ломается сценарий без антипетли: ответ бота снова попадает в Watch Updates и крутит лавину.

Прогресс: три модуля на холсте, Filter стоит до Reply.

Проверьте один ответ со второго аккаунта

До постоянного режима нужен честный прогон. Не включайте сценарий «на удачу» – сначала один ручной запуск.

  1. Запустите Run once (один ручной запуск) в Make.
  2. Со второго аккаунта напишите боту короткое текстовое сообщение.
  3. Проверьте чат: пришёл ровно один заранее заданный ответ.
  4. Проверьте History (журнал запусков): прогон зелёный, без красных ошибок на Filter и Reply.
  5. Напишите ещё раз сразу: второй ответ – один, без лавины «сам себе».
  6. Только после этого включите сценарий ON (постоянный режим).
  7. Если бот молчит – сначала /start, один Watch Updates, ослабьте Filter и повторите Run once.

Результат: со второго аккаунта приходит один шаблонный текст, Filter режет пустые и «свои» апдейты, сценарий ON. Sheets на этом вечере не обязателен – это другой гайд про заявки.

Прогресс: один спокойный автоответ, петли нет.

Чеклист поломок и что дальше

Короткий чеклист перед потоком клиентов:

  1. Избегайте второго Watch Updates на того же бота.
  2. Проверьте, что токен не «уехал» в публичный чат.
  3. Уберите из Filter условие «любое входящее» без проверки текста и is_bot.
  4. Не делайте MVP через userbot и серые скрипты – риск бана, не для новичка с лидами.
  5. Добавьте запись в таблицу позже по гайду заявок – после стабильного Reply.

Частые вопросы

Чем автоответчик в Make отличается от Telegram Premium Away?

Away – статичная отбивка у Premium-аккаунта. Make-сценарий – свой бот и шаблонный ответ без подписки. Выбирайте Away, если нужна короткая фраза «не у компьютера»; бота – если нужен контролируемый автоответ и дальше ветки в Make.

Нужен ли Premium, чтобы бот отвечал клиентам?

Нет. Premium Away – отдельный контур. Бот из @BotFather плюс Make отвечает без Premium. Подписка не обязательна для MVP с одним шаблонным текстом.

Почему бот отвечает сам себе и спамит?

Watch Updates ловит и собственные ответы бота. Добавьте Filter: текст есть + не от бота. Один триггер на бота. После правки – Run once со второго аккаунта.

Чем этот гайд отличается от бота заявок в Google Sheets?

Там цель – строка в таблице. Здесь – мгновенный ответ в чате; Sheets не обязателен. Когда автоответ стабилен, допишите запись по гайду заявок.

Куда девать токен BotFather?

Только в connection Make и менеджер паролей. Не в чат клиенту и не в публичный GitHub. Утечка токена = полный контроль над ботом у посторонних.

Подойдёт ли шаблонный автоответ без ИИ в первый вечер?

Да. Один спокойный текст держит диалог. ChatGPT и длинные ветки – следующий шаг, когда Run once уже зелёный и петли нет.

Бот молчит после включения – что проверить первым?

Проверьте /start со второго аккаунта, один Watch Updates, Filter не режет тестовое сообщение, затем Run once и History. Постоянный режим включайте после одного успешного ответа.
