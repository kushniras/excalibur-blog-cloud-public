Олег скопировал "готовый" JSON из YouTube, вставил один HTTP в Make и ждал пост в Threads. Вместо ленты – ошибка контейнера. Три дня он снова публиковал с телефона: казалось, автопостинг в тредс "только для программистов". На деле не хватало второго шага и паузы. Ниже – таблица в Google Sheets и сценарий Make, чтобы за вечер увидеть тестовый текст в своём аккаунте.

Когда автопостинг в Threads не включать

Если аккаунт не прогрет и нет ручных постов – очередь в Make рано. Если тексты сырые – сначала ручная выкладка. Типичная ошибка: одинаковые посты пачкой. На практике Sheets → один тестовый пост → лимит в день.

На практике очередь в Sheets спасает от хаоса вкладок, но не от бана: одинаковые посты пачкой – типичная ошибка. Живой пример: один тестовый слот → проверка текста в Threads → только потом дневной лимит.

Суть простыми словами: официальный Threads API не умеет "одну кнопку Publish". Сначала создаёте черновик (контейнер), ждёте около 30 секунд, потом выкладываете. Сделайте строку со статусом "готово" в Google Sheets, два модуля HTTP из apps.make.com/http и Sleep между ними – и первый тестовый пост появится в ленте без кода и без VPS.

Боль новичка понятна: токен Meta выглядит страшно, а холодный спам ссылок пугает баном. Ориентир на сегодня – один короткий текст без ссылки, зелёный History в Make и статус "опубликовано" в таблице. Картинки и карусели оставьте на потом.

Почему один HTTP не выкладывает тредс пост

В реальном проекте люди ждут, что Make "нажмёт Publish" одним кубиком. В документации Meta иначе: сначала POST на создание контейнера, затем POST на threads_publish с id этого контейнера. Контейнер – черновик на стороне Meta. Publish – уже выложить в ленту. Пока черновик не обработан, второй запрос отвечает ошибкой – и кажется, что "API сломан".

Важный факт для первых 30% чтения: в Threads API нет одной кнопки Publish. Официально всегда create → ждать ~30 секунд → publish. Плюс лимит 250 API-постов на профиль за скользящие 24 часа и long-lived токен примерно на 60 дней. Текст – до 500 символов. Не делайте пачку из десяти ссылок в первый вечер: сначала один безопасный тест без URL.

На практике тот же Sheets→Make-паттерн уже есть для Instagram и MAX. Разница Threads – хост graph.threads.net и обязательные два шага. Избегайте гайдов, где показывают только один HTTP: типичная ошибка Олега. Конкуренты часто уводят в SaaS-календарь или VPS с Cron – вам для первого вечера это не нужно.

Подготовьте токен Meta и таблицу Google Sheets

Сделайте аккаунт Threads живым до автопоста. Если аккаунт свежий или долго молчал, сначала пройдите прогрев аккаунта – это снимает страх "сломаю баннером ссылок".

  1. шаг 1: в Meta Developers создайте приложение с продуктом Threads API;
  2. шаг 2: выдайте права threads_basic и threads_content_publish;
  3. шаг 3: получите user token и обменяйте short-lived (около часа) на long-lived (около 60 дней);
  4. шаг 4: сохраните токен только в connection Make – не в чатах и не в публичной таблице;
  5. шаг 5: в Google Sheets заведите колонки text, status, posted_at (опционально media_url);
  6. шаг 6: добавьте одну тестовую строку: короткий текст без ссылки, статус готово, длина меньше 500 символов.

Проверьте, что в строке нет "закрытого" Drive-URL для картинки. Для новичка старт – только TEXT: Meta сама скачивает IMAGE/VIDEO по публичному HTTPS, а "ссылка для себя" в Drive ломает пост. Используйте публичный URL только когда текст уже стабильно уходит. Карусель и видео оставьте вторым этапом – после зелёного текстового прогона.

Например, текст "Тест автопоста из таблицы, день 1" – нормальный ориентир. Не вставляйте UTM и внешние ссылки в первый прогон; метки пригодятся позже по гайду UTM для автопостинга. Если токен внезапно "Authorization Failed", почти всегда истёк short-lived или забыли обновить long-lived в connection – это чинится за минуту, без пересборки всего сценария.

Соберите workflow Make: два HTTP и Sleep

Откройте Make и соберите цепочку кубиков. Канон HTTP-модуля – Make HTTP; для соседних Telegram-сценариев удобен вход через apps.make.com/telegram. Не ведите читателя на www.make.com: боты часто ловят 403.

  1. Google Sheets → Watch Rows (или Search Rows) по листу с постами;
  2. Filter: только строки со статусом готово;
  3. HTTP #1: POST https://graph.threads.net/v1.0/{threads-user-id}/threads с полями media_type=TEXT, text из ячейки, access_token;
  4. Parse response и сохраните id контейнера;
  5. Sleep около 30 секунд (как рекомендует Meta);
  6. HTTP #2: POST …/threads_publish с creation_id = id контейнера;
  7. Google Sheets Update Row: статус опубликовано, posted_at = сейчас.

Схема workflow одной строкой: Watch Rows → Filter "готово" → HTTP create → Sleep → HTTP publish → Update Row. Добавьте в scenario только одну тестовую строку, пока оба HTTP не станут зелёными. Уберите из первого прогона любые модули "рассылки пачкой" – они мешают увидеть ошибку контейнера. Часто ломается на мелочи: забыли media_type=TEXT, не передали creation_id, или Sleep стоит 5 секунд вместо ~30.

Если не хотите собирать HTTP руками после первого успеха, в папке блюпринтов Make и в канале Ковчег есть линейка Threads-модулей (#1177) и обновление авторизации (#1282), чтобы реже крутить токен каждые 60 дней. Но для обучения two-step руками полезнее: вы поймёте, где ломается "один HTTP". Open-source CLI и MCP вокруг Threads API тоже подтверждают ту же схему container → publish – это не "выдумка блога", а официальный поток Meta.

Прогоните Run once и зафиксируйте первый пост

Нажмите Run once на сценарии. Проверьте History: оба HTTP зелёные, между ними виден Sleep. Затем откройте приложение Threads – тестовый текст из строки таблицы должен быть в ленте. В таблице статус должен смениться на "опубликовано".

Критерий успеха до FAQ: History зелёный на двух HTTP, статус в Sheets обновлён, пост виден в приложении, токен не светится в чатах, пауза ~30 с между create и publish есть. Если красный только второй HTTP – почти всегда рано нажали publish или забыли creation_id. Если красный первый – смотрите media_type, длину текста и токен.

Сделайте второй прогон только после зелёного первого. Не делайте десять строк "готово" подряд в первый вечер: лимит 250/сутки щедрый, но платформа всё равно смотрит на поведение нового автопоста. Контент на неделю удобно держать в том же духе, что и контент-план в Google Sheets.

Чеклист запуска: не сожгите аккаунт автопостом

Перед регулярным автопостингом в тредс пройдите короткий чеклист. Он закрывает страх бана и типичные дыры YouTube-роликов.

  • Первый пост – TEXT без ссылки; медиа – только после стабильного текста.
  • Sleep ~30 с между create и publish; при серии постов – пауза и между строками.
  • Long-lived токен в connection Make; календарь refresh на ~60 дней.
  • Не копируйте URL www.make.com и help.make.com/http в сценарий – канон apps.make.com/http.
  • Ссылки и UTM – после прогрева; одна таблица на несколько сетей возможна, но endpoints не смешивайте (см. также Telegram+VK).
  • Стек Make vs n8n для маркетинга – отдельное сравнение: Make или n8n.

Избегайте "холодного" автопоста с пачкой внешних ссылок в день нулевой. Ориентир Meta: 250 API-постов / 24 ч – потолок, не план на спам. Используйте одну живую строку как контрольный образец каждую неделю, если меняли токен или модули.

Частые вопросы

Есть ли готовый модуль Threads в Make или нужен HTTP?

Для новичка канон – HTTP через apps.make.com/http: так видно create → Sleep → publish. Когда two-step освоен, можно подключить кастомные Threads-модули из папки блюпринтов и постов канала (#1177).

Как получить токен Threads без программиста?

Зайдите в Meta Developers, создайте app с Threads API, выдайте threads_basic и threads_content_publish, сгенерируйте user token и обменяйте на long-lived (около 60 дней). Сохраните токен только в connection Make.

Чем автопостинг в тредс отличается от Instagram?

Паттерн таблицы тот же: статус "готово" → сценарий → "опубликовано". Отличие – endpoints на graph.threads.net и обязательные два HTTP плюс пауза ~30 с. Instagram-гайд: автопостинг Instagram через Sheets.

Нужен ли прогрев перед автопостом?

Да, особенно перед ссылками. Сначала живой аккаунт и ручные ответы, потом один тестовый TEXT без URL, затем регулярный график. Подробный порядок – в материале про прогрев перед автопостингом.

Можно ли брать текст из той же таблицы, что для VK и Telegram?

Да: отдельные колонки статуса или отдельные листы. Не мешайте publish-эндпоинты разных сетей в одном HTTP. Для связки TG+VK смотрите автопостинг Telegram и VK.

Почему картинка не уходит в пост?

Часто media_url закрыт или не HTTPS. Сделайте стабильный TEXT, затем IMAGE только с публичным URL, который Meta может скачать сама. Drive "для себя" – типичная ошибка.
