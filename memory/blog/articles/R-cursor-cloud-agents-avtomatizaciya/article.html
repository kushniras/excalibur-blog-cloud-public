Марина каждое утро руками собирает бриф по конкурентам: открывает Cursor, копирует ссылки, ждёт ответ, переносит текст в Notion. Уехала на встречу – бриф не готов, реклама ушла без тезисов. Боль знакома многим: кажется, что AI-агенты для бизнеса 24/7 – только для программистов, Make уже "не тянет" длинное рассуждение, а в Cursor страшно сжечь бюджет. Ответ проще: одна утренняя Automation с cron, секреты в Dashboard и один артефакт без ручного пинания IDE.

Когда Cloud Agents и Automations не нужны

Если задача разовая и вы у экрана – обычный чат в IDE дешевле и проще. Если нужен только перевод строки между Google Sheets и Telegram – начните с Make, не с облачного агента. Типичная ошибка: включить Automation без критерия "готово" и жечь лимиты ночными прогонами.

Сравните роли: чат в IDE, Cloud Agent, Automation и Make

Боль "не понимаю, чем чат отличается от облака" снимается таблицей. Чат в Cursor – вы у ноутбука и пинаете диалог. Cloud Agent – сотрудник в облаке: виртуальная машина крутится без вас. Automation – будильник или звонок: cron (расписание) или webhook (сигнал из Make/CRM). Make/n8n – линейные кнопки if→then: хорошо для "письмо ушло", плохо для "сравни три сайта и напиши бриф".

Инструмент На пальцах Когда брать
Чат в IDE Диалог, пока открыт ноутбук Разовый вопрос, правка глазами
Cloud Agent Разовый прогон в облаке Нужен артефакт, вас нет у экрана
Automation Триггер 24/7 + Max Mode Одна и та же задача каждое утро
Make / n8n Линейные шаги и кнопки Фильтры, таблицы, уведомления без "длинного мышления"

Вердикт: не делайте из первого дня "цифрового сотрудника на всё". Используйте Automation с cron для утренней задачи; Make оставьте glue-слоем. Канон – в Cursor Docs: Cloud Agents и Automations.

Связка Make + MCP уже разобрана отдельно – Make AI Agents и MCP. Офис субагентов в IDE (research + draft) – другая история: AI-агент для маркетинга в Cursor. Здесь фокус на расписании в облаке.

Выберите одну повторяющуюся задачу и критерий "готово"

Типичная ошибка Марины – отдать агенту "весь маркетинг". На практике берите одну боль недели. Например: утренний бриф по трём конкурентам, черновик поста или RSS-дайджест в Telegram. Критерий готово – не "ИИ подумал", а файл md, сообщение в тестовом канале или черновик в Notion.

  1. Шаг 1. Запишите одной фразой задачу недели (бриф / пост / дайджест).
  2. Шаг 2. Назовите артефакт: какой файл или сообщение появится утром.
  3. Шаг 3. Опишите "готово" в двух предложениях: длина, структура, без воды.
  4. Шаг 4. Уберите из ТЗ всё, что не относится к этой одной задаче.
  5. Шаг 5. Решите: хватит Make (линейные шаги) или нужен агент, который "подумает".
  6. Шаг 6. Добавьте запрет: токены и пароли не писать в промпт и не класть в git.

В реальном проекте этот список спасает от "ещё одного универсального помощника". Избегайте формулировок вроде "будь полезным маркетологом 24/7" – промпт Automation должен быть коротким: вход, формат выхода, куда положить результат.

Соберите первую Automation: trigger, prompt и безопасный запуск

Боль "сломаю репозиторий и солью токены" закрывается безопасным первым циклом. Для Cloud Agents нужен платный план Cursor и подключённый GitHub (или GitLab/Bitbucket). Секреты – только в Dashboard → Cloud Agents → Secrets, не в коде. MCP на пальцах – "розетка" к внешним сервисам: Telegram, таблицы, поиск; подключайте только то, что нужно задаче.

  1. Шаг 1. Подключите репозиторий к Cursor и убедитесь в paid plan.
  2. Шаг 2. Выставьте spend limit в dashboard – ориентир: запас около $2 под hard limit.
  3. Шаг 3. Сделайте запись секретов (TELEGRAM_BOT_TOKEN и аналоги) только в Dashboard Secrets.
  4. Шаг 4. Создайте Automation на cursor.com/automations или через /automate.
  5. Шаг 5. Выберите trigger: cron "каждое утро" или webhook из Make.
  6. Шаг 6. Напишите короткий prompt с форматом выхода; модель – Composer, не Opus.
  7. Шаг 7. Для маркетинга без правок кода используйте no-repo + MCP; для пайплайна вроде RSS→TG укажите repo.

Webhook на пальцах – ссылка-звонок: Make дергает URL, агент просыпается. URL и ключ появляются после Save automation. Beginner-сценарий: rss-ai-telegram (один запуск = один пост). Cloud-пайплайн блога – excalibur-blog-cloud-public; офис страниц – nero-network-office-page.

Схема первого вечера:
Одна задача → paid plan + spend limit → Secrets → Automation (cron/webhook) → Composer → Test run → артефакт

Если MCP ещё не настроен – подключение MCP в Cursor. Не делайте сразу контент-завод на десяток агентов: сначала стабильный утренний цикл, потом автономный контент-завод.

Прогоните один цикл и проверьте стоимость

Боль "солю бюджет на первом агенте" лечится одним тест-прогоном. Сделайте Test run или ручной Cloud Agent цикл. Проверьте, что артефакт появился в безопасном месте (тестовый канал, отдельная ветка, папка drafts). Затем откройте usage dashboard: Cloud Agents сначала едят included API usage (на Pro от $20/мес), потом on-demand.

  • Проверьте, что Automation в статусе Active.
  • Проверьте, что секреты читаются и токена нет в git.
  • Используйте Composer для рутины; Opus high-thinking оставьте редким сложным разборам.
  • Добавьте в заметку фактический расход первого прогона – это ваш ориентир на завтра.

Честно: Automations всегда в Max Mode, бесплатно "навсегда" не будет. Типичная ошибка – hourly cron на тяжёлой модели. Для брифа хватит утреннего запуска. Паттерн "Make как glue + Cursor думает" уже у Mattermost: n8n дергает событие, агент пишет разбор.

Чеклист на завтра: что должно работать без вас

До FAQ зафиксируем success criteria. Вы поймёте, что всё сработало, если утром есть готовый артефакт без открытия IDE, секреты только в Dashboard, Automation Active и лимит не упёрся в ноль.

  1. Шаг 1. Откройте dashboard и убедитесь, что Automation Active.
  2. Шаг 2. Проверьте, что критерий "готово" выполнен (файл / TG / черновик).
  3. Шаг 3. Убедитесь, что в репозитории нет токенов – уберите их, если всплыли.
  4. Шаг 4. Сверьте расход с ориентиром первого Test run.
  5. Шаг 5. Повторите цикл на следующий день без ручных правок промпта.
  6. Шаг 6. Только после двух стабильных утр добавьте второй MCP или webhook из CRM.

Этот чеклист – фильтр от хаоса. Избегайте усложнения "на всякий случай": сначала один артефакт в день. Make + вайбкодинг рядом с агентами – в курсе на kv-ai.ru и в канале Ковчег.

Частые вопросы

Чем Cloud Agents отличаются от Make?

Make и n8n гоняют линейные шаги: фильтр, запись, уведомление. Cloud Agent думает длиннее: сравнивает источники, пишет бриф, правит файлы в репозитории. Сделайте правило: кнопки – в Make, рассуждение по расписанию – в Cursor Automation. Связку через webhook используйте, когда событие в Make должно разбудить агента.

Нужны ли Automations новичку-маркетологу?

Да, если одна и та же задача повторяется каждое утро и вы устали сидеть у чата IDE. Не делайте десять автоматизаций сразу: хватит одного cron на бриф или RSS→TG. Если задача разовая – достаточно ручного Cloud Agent run.

Сколько стоит первый агент?

Нужен paid plan (индивидуальный Pro от $20/мес с API usage). Расход Cloud Agents идёт по API-цене модели; Automations всегда в Max Mode. Проверьте spend limit до первого запуска и начните с Composer. Точную цифру "за бриф" заранее не обещают – смотрите usage после Test run.

Когда лучше оставить задачу в Make?

Оставляйте в Make, если шаги предсказуемые: "если новая строка → отправить сообщение". Переносите в Automation, когда нужно сравнить, сформулировать и собрать текст. Избегайте дублирования: не гоняйте один и тот же бриф и в Make AI, и в Cursor без критерия "готово".

С какой задачи начать создание ai агентов?

С узкой: утренний бриф, черновик поста или дайджест RSS. Добавьте критерий файла/сообщения и один Test run. Готовый шаблон – репозиторий rss-ai-telegram; для обучения работе с ai агентами смотрите разборы #1314 в канале и docs Cursor, а не абстрактные "платформы ai агентов" без кнопки запуска.

Есть ли бесплатные ai агенты в Cursor Cloud?

Бесплатного always-on Cloud/Automations навсегда нет: нужен платный план и API usage. Бесплатные ai агенты в рекламе обычно про демо или локальные чаты. Для бизнеса честный путь – маленький лимит, дешёвая модель и один стабильный цикл, а не обещание "бесплатно 24/7".
