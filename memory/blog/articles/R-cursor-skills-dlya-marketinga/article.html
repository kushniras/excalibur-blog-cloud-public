Rules, Skills и плагины кажутся "кодом", и снова открываются заметки. Хватит копировать вчерашний промпт: за вечер через /create-skill сделайте один SKILL.md, завтра вызывайте /brief-post и получите тот же сценарий без промпта с нуля.

Когда Skill не нужен

Если задача разовая – "перепиши заголовок" – хватит промпта в чате, не плодите SKILL.md. Если тон команды ещё не зафиксирован, сначала короткое правило alwaysApply, иначе Skill будет ломаться от споров о голосе бренда. Типичная ошибка: смешать Skill, Rules и плагин в один вечер. На практике один навык на один повторяемый бриф.

Cursor Skills – это не "магия для разработчиков", а файл-рецепт: шаги задачи в SKILL.md, вызов по имени через слэш. Skill появляется по запросу; Rule висит в фоне всегда; плагин – готовый пакет из нескольких кусков. Skills в Cursor с релиза 2.4 (22 января 2026) – открытый стандарт Agent Skills. Разберите, чем Skill отличается от Rules, чата и плагина

Боль "всё кажется кодом, страшно сломать проект" лечится простой кухней. Чат Cursor – разговор с нуля: каждый раз объясняете заново. Rule – табличка на стене: "всегда пиши на русском, не трогай секреты". Skill – рецепт в блокноте: открыли, когда нужно бриф или UTM. Плагин – коробка с несколькими рецептами и правилами сразу.

На практике новичок путает четыре ярлыка и ставит зоопарк "на всякий случай". Ориентир из Help Cursor: Rules – короткие guidelines always-on; Skills – multi-step workflow по запросу. Docs по субагентам прямо советуют: для одной повторяемой цели берите skill, а не отдельного агента. Не делайте день-1 из плагина и трёх skills сразу.

Выберите одну маркетинговую задачу на вечер

Боль "хочу сразу SEO, Метрику и всё сразу" закрывается жёстким фильтром: одна повторяемая задача. Типичная ошибка – пять skills за ночь и ни одного стабильного вызова. Например, Лена выбрала "бриф Telegram-поста": вход (оффер, аудитория), шаги, критерий "готово".

Сделайте выбор из трёх безопасных стартов: бриф поста (тон + CTA + запреты), таблица UTM под кампанию, чеклист перед публикацией. Не делайте skill "на весь маркетинг": агент размажет шаги. Избегайте чужих тяжёлых репозиториев в вечер-1 – сначала свой файл на 15–30 строк.

  1. Шаг 1. Выпишите рутину, которую повторяете каждую неделю одним абзацем.
  2. Шаг 2. Проверьте, что входные данные умещаются в чат (оффер, ссылка, тон) – без секретов.
  3. Шаг 3. Назовите навык латиницей через дефис: brief-post, utm-table, publish-checklist.
  4. Шаг 4. Зафиксируйте критерий "готово": файл в briefs/ или checklists/, пункты сверяемы глазами.
  5. Шаг 5. Уберите из списка всё "на будущее" – один skill, один вечер.
  6. Шаг 6. Добавьте в заметку фразу "завтра снова /имя" – это ваш тест успеха.

Surprising fact из community forum: папка ~/.cursor/skills-cursor/ – системная; файлы там молча пропадают. Кладите навыки в .cursor/skills/ проекта или ~/.cursor/skills/. И ещё: при зоопарке skills description в автоподборе укорачивается – критичный навык лучше звать явно через /.

Создайте SKILL.md через /create-skill без кода

Боль "skills только для разработчиков" снимается встроенной командой. В Agent chat наберите /create-skill и опишите задачу человеческим языком: "нужен бриф поста: тон, CTA, UTM, запреты". Cursor соберёт структуру и SKILL.md. Альтернатива: вручную папка .cursor/skills/brief-post/SKILL.md.

Обязательные поля frontmatter: name (lowercase, дефисы, = имя папки) и description (что делает + когда вызывать). В теле – вход → действия → критерий готово. Секреты (токены, пароли) – только в env, не в тексте навыка. Используйте короткий description: агент читает его при автоподборе.

  1. Шаг 1. Откройте Agent chat в проекте маркетинга (не пустой sandbox "на потом").
  2. Шаг 2. Наберите /create-skill и опишите рутину своими словами – код писать не нужно.
  3. Шаг 3. Проверьте путь: файл должен лежать в .cursor/skills/<имя>/SKILL.md, не в skills-cursor.
  4. Шаг 4. Сверьте frontmatter: name совпадает с папкой, description отвечает на "когда звать".
  5. Шаг 5. Добавьте в тело чеклист шагов и явный критерий "готово" (куда сохранить артефакт).
  6. Шаг 6. Уберите из файла ключи API и пароли, если агент их предложил "для удобства".
  7. Шаг 7. Откройте Customize → Skills и убедитесь, что навык виден в списке.

В реальном проекте правят SKILL.md час, но забывают новый чат – агент "не видит" правку. Проверьте: новый Agent-чат после сохранения. Опционально: disable-model-invocation: true, если нужен только явный /.

name: brief-post
description: Бриф Telegram-поста: тон, CTA, UTM, запреты. Вызывать, когда нужен повторный бриф без промпта с нуля.
Тело: 1) спросить оффер и аудиторию 2) собрать бриф 3) сохранить в briefs/slug.md 4) критерий готово – все пункты заполнены.

Запустите первый прогон и повторите завтра

Боль "сделал skill, а агент молчит / фантазирует" закрывается явным слэшем и артефактом на диске. В чате наберите /brief-post (или ваше имя). Попросите сохранить результат в папку проекта. Глазами сверьте пункты – не "лайкните ответ в чате".

  1. Шаг 1. Вызовите навык через /имя-навыка в Agent chat.
  2. Шаг 2. Дайте свежие входные данные (новый оффер), не копируйте вчерашний простынёй промпт.
  3. Шаг 3. Дождитесь файла в briefs/ или checklists/ – это ваш результат вечера.
  4. Шаг 4. Проверьте, что порядок шагов совпал с SKILL.md, а не "креатив агента".
  5. Шаг 5. На следующий день снова /имя-навыка на других данных – тот же порядок = успех.

Часто ломается автоподбор: агент "забыл" skill среди десятка описаний. Используйте явный / – community прямо пишет, что description truncates в начальном контексте. Workflow закрепления: вызов → файл → повтор завтра.

Чеклист day-1 и что смотреть после своего первого навыка

Боль "хочется сразу SEO+GEO / Метрику и тону в чужом репо" лечится очередью. Сначала свой короткий skill. Потом – готовые примеры как next-step, не как замена первому вечеру.

Чеклист перед тем как ставить чужое:

  • В проекте одна папка .cursor/skills/<имя>/ с SKILL.md.
  • Customize → Skills видит навык; вызов через / даёт артефакт.
  • В файле нет секретов; description понятен человеку без жаргона.
  • Завтрашний повторный / даёт тот же порядок шагов.

Готовые якоря после своего первого: наставник Cursor Junior (когда rule vs skill vs MCP), SEO+GEO skill на GitHub, skill Метрики yandex-metrika-assistant. Соседние гайды: SEO-аудит через skill, Метрика API в Cursor, субагенты – AI-агенты для маркетинга. Вайбкодинг-вход – вайбкодинг в Cursor.

Системный разбор автоматизаций рядом с Cursor – в курсе Make.com и вайбкодинга; skill вечера от курса не зависит. Разборы инструментов: @maya_pro.

Критерий успеха до FAQ: есть .cursor/skills/<имя>/SKILL.md с name+description; /имя-навыка сохраняет бриф, UTM или чеклист в папку проекта; повторный вызов на следующий день повторяет тот же порядок шагов. Это и есть first-win без команды разработчиков.

Частые вопросы

Чем cursor skills отличаются от rules?

Rule – короткое правило всегда в фоне (тон, язык, запреты). Skill – пошаговый сценарий по запросу: бриф, UTM, чеклист. Начните с одного skill на рутину; rules добавьте позже коротко.

Как создать skill без кода?

В Agent chat наберите /create-skill и опишите задачу своими словами. Либо создайте папку .cursor/skills/имя/SKILL.md с name, description и шагами. Проверьте, что файл не в skills-cursor.

Нужен ли плагин, чтобы пользоваться skills?

Нет. Плагин – пакет (rules + skills + агенты + MCP). Свой SKILL.md работает без Marketplace. Плагин ставьте после того, как один свой skill уже вызывается через /.

Можно ли вызвать skill через слэш /?

Да. В Agent chat пишите /имя-навыка. Так надёжнее автоподбора: при большом каталоге description укорачивается. Для критичных навыков используйте явный слэш.

С какого навыка начать маркетологу?

С одной еженедельной рутины: бриф поста, таблица UTM или чеклист публикации. Не SEO+GEO и не Метрика в вечер-1 – сначала свой короткий файл, потом готовые skills с GitHub.

Куда класть SKILL.md и почему не skills-cursor?

В .cursor/skills/ проекта или ~/.cursor/skills/. Папка ~/.cursor/skills-cursor/ системная: community пишет, что файлы там не сохраняются. После создания откройте Customize → Skills.

Чем skill отличается от готового плагина из маркетплейса?

Skill – один рецепт в SKILL.md. Плагин – раздаваемый набор. Сначала сделайте свой навык; Junior, SEO+GEO и Метрику подключайте как следующий шаг, не вместо first-win.
