Дима ведёт блог через Make: пост → сайт → Telegram. Статьи выходят три раза в неделю, а в Яндексе «новые» появляются через неделю. Друг сказал «включи IndexNow» – Дима увидел JSON и ключ .txt и испугался, что сломает домен. Боль знакома: API кажется только для программистов. Ответ проще: ключ как файл в корне + один HTTP POST в Make после публикации – и тестовый URL уходит с кодом 200 или 202.

IndexNow – это вежливый стук роботу: «вот новый или изменённый URL, посмотри». Не гарантия позиций и не замена sitemap. Яндекс принимает уведомления на yandex.com/indexnow; один POST может охватить до 10 000 адресов и шарится между Bing, Yandex, Naver, Seznam и Yep. Сюрприз 2026: Google протокол до сих пор не принимает. Ориентир на вечер: ключ открывается в браузере как текст → сценарий Make → HTTP 200/202 на один тестовый URL.

Parent-запрос «indexnow» даёт около 230 показов в месяц по России (Wordstat, регион 225, прогон 12.07.2026). Рядом ищут «яндекс indexnow», «api indexnow» и хвосты про то, как ускорить индексацию. Ниже – workflow для новичка без CMS-плагина: сначала ключ, потом один модуль Make, потом проверка без паники на коде 202.

Зачем IndexNow, если уже есть sitemap

Sitemap – это карта сайта: «вот все страницы, которые можно обойти». Робот приходит когда захочет. «Переобход страниц» в Яндекс.Вебмастере – ручная кнопка на каждый URL. IndexNow – сигнал сразу после публикации: вы сами говорите, что страница появилась или изменилась.

Способ Что делает Кому подходит
Sitemap Карта для регулярного обхода Всегда нужна, в том числе для Google
Переобход в Вебмастере Ручной запрос по URL Разовые правки, мало страниц
IndexNow (Яндекс/Bing…) POST/GET с списком URL Контент-завод, частые публикации
Google Indexing API / GSC Отдельный стек Google Не закрывается пингом IndexNow

Итоговый вердикт: не делайте ставку на один пинг как на «мгновенные позиции». Используйте IndexNow как ускоритель сигнала для Яндекса и партнёров протокола, а sitemap оставьте фундаментом. Для Google смотрите Search Console и карту сайта – подробнее в гайде про robots.txt и sitemap.

На практике амбассадор Яндекса Михаил Сливинский (март 2026) отдельно подчёркивает: IndexNow и обход по Метрике чаще нужны вместе. IndexNow полезен для страниц, на которых ещё нет трафика – как раз ваш свежий пост из контент-завода.

Как положить ключ IndexNow на сайт без страха

Ключ – это обычный текстовый файл, не «взлом домена». По докам Яндекса: 8–128 символов из латиницы, цифр и дефиса, UTF-8, без HTML. Рекомендуемый путь – корень сайта: https://ваш-сайт.ru/ВАШКЛЮЧ.txt. Откройте ссылку в браузере: должны увидеть только строку ключа, как у favicon – файл лежит и отдаётся.

  1. Шаг 1: Сгенерируйте строку 8–128 символов (латиница, цифры, дефис).
  2. Шаг 2: Создайте файл с именем ключ.txt и положите в корень хостинга или в public/.
  3. Шаг 3: Откройте URL файла в браузере по HTTPS.
  4. Шаг 4: Убедитесь, что на странице нет шаблона сайта, пробелов вокруг и тегов.
  5. Шаг 5: Если ключ не в корне – укажите точный keyLocation в запросе.
  6. Шаг 6: Для поддомена сделайте отдельный ключ (правило Яндекса).

Типичная ошибка старта (и в open-source CLI вроде jtprogru/indexnow, и в community): файл не отдаётся, отдаёт HTML 404-шаблона или лежит не там, куда смотрит keyLocation. Тогда приходит 403 или 422. Проверьте ключ глазами до любого сценария Make – это снимает страх «сломаю сайт».

Сделайте: сначала verify в браузере. Не делайте: коммитить ключ в публичный репозиторий «на всякий случай» без плана ротации, если репозиторий открыт всему интернету.

Соберите сценарий Make: publish → IndexNow

API (Application Programming Interface) здесь – просто адрес, куда Make шлёт короткое сообщение. Модуль HTTP «Make a request» умеет POST так же, как для любого другого сервиса. Endpoint Яндекса: https://yandex.com/indexnow. Тело JSON: host, key, urlList (массив адресов, до 10 000 за раз), при необходимости keyLocation.

Схема workflow:
Публикация статьи → триггер Make (webhook / RSS / таблица) → HTTP POST на yandex.com/indexnow → запись кода ответа в лог или Google Sheet

  1. Шаг 1: Возьмите один свежий URL статьи, не весь архив блога.
  2. Шаг 2: Добавьте модуль HTTP Make a request после шага публикации.
  3. Шаг 3: Метод POST, URL https://yandex.com/indexnow, Content-Type application/json.
  4. Шаг 4: В теле передайте host без https, key и urlList с одним тестовым адресом.
  5. Шаг 5: Запустите сценарий один раз вручную.
  6. Шаг 6: Прочитайте статус: 202 или 200 – успех сигнала; 403/422 – чините ключ или host.
  7. Шаг 7: Добавьте в лог поля URL, время и HTTP-код, чтобы видеть живой пайплайн.

Например, в канале @maya_pro #1272 уже разбирали модуль автоматизации Index NOW Yandex для Make. Готовые сценарии лежат в папке блюпринтов – можно взять шаблон вместо ручной сборки HTTP. Если ведёте автономный контент-завод, этот пинг логично вешать сразу после публикации на сайт – см. также материал про контент-завод на нейросетях.

Используйте debounce: один и тот же URL не чаще чем раз в 10 минут (рекомендация Яндекса). При 429 Slow down – пауза и повтор, как делают submitter-скрипты на GitHub. Избегайте заливки всего сайта «на всякий случай»: IndexNow – только новые, изменённые или удалённые страницы.

Проверьте ответ: 200, 202 и Вебмастер

Код 202 Accepted часто пугает новичков: кажется, что «не приняли». По справке Яндекса 202 значит, что ключ ещё проверяется. Подождите и отправьте ещё один-два URL. 200 – принято. 403 – ключ не загрузился или не подходит. 422 – неверный URL, host или ключ. 429 – слишком часто.

  1. Шаг 1: Откройте историю выполнения сценария Make и найдите HTTP-модуль.
  2. Шаг 2: Зафиксируйте код ответа рядом с тестовым URL.
  3. Шаг 3: Если 202 – подождите и повторите тест, не пересобирая ключ сразу.
  4. Шаг 4: Если 403/422 – вернитесь к файлу ключа и совпадению host.
  5. Шаг 5: В Яндекс.Вебмастере посмотрите, что URL ушёл в очередь на обход (без обещания мгновенного индекса).
  6. Шаг 6: Уберите из сценария массовую отправку старых архивных URL «для галочки».

Честно говоря, индексация не гарантируется даже при 200 – Яндекс прямо пишет, что протокол ускоряет уведомление, а не «покупает» место в выдаче. Связка с видимостью в нейроответах – отдельная тема GEO-оптимизации: IndexNow лишь быстрее зовёт робота к свежей странице.

Чеклист антиспама перед продакшн-пингами

Перед тем как пустить workflow на все новые статьи, пройдите короткий чеклист. Он закрывает боль «шлю всё подряд и ловлю 429».

  • Ключ открывается в браузере как чистый текст.
  • В Make уходит только новый или реально изменённый URL.
  • Один URL не дублируется чаще чем раз в 10 минут.
  • В логе есть код ответа на каждый пинг.
  • Sitemap по-прежнему обновляется и доступен.
  • Ожидания по Google отделены: этот пинг его не кормит.
  • Опционально включён обход по Метрике в Вебмастере – рядом, не вместо IndexNow.
  • Нет массовой заливки всего домена «на всякий случай».

Критерий «готово» за вечер: ключ-файл открывается; тестовый URL из Make вернул 200 или 202; в истории сценария есть успешный HTTP-модуль; вы понимаете, что Google этим пингом не покрывается и sitemap всё ещё нужен. Это и есть success criteria – без команды разработчиков и без ручного переобхода каждой страницы.

Частые вопросы

Нужен ли IndexNow, если уже есть sitemap?

Да, как дополнение. Sitemap остаётся картой для регулярного обхода. Сделайте IndexNow поверх: он ускоряет сигнал о свежих URL. Уберите идею «или то, или другое» – для стабильного SEO нужны оба слоя.

Работает ли IndexNow для Яндекс.Дзена?

IndexNow уведомляет поисковых участников протокола о URL сайта, а не заменяет публикацию в Дзен. Если статья живёт на вашем домене и вы хотите быстрее позвать Яндекс к странице – пинг уместен. Для ленты Дзена используйте свой канал публикации отдельно.

Как часто слать один и тот же URL?

Не делайте частые повторы. Ориентир Яндекса – пауза не меньше 10 минут для одного адреса; FAQ IndexNow.org советует debounce от 5 минут. На практике достаточно пинга при реальной публикации или заметном изменении.

Что делать, если API вернул ошибку?

Проверьте код: 403/422 – файл ключа и host; 429 – замедлите сценарий и добавьте паузу. При 202 подождите и повторите тест. Используйте лог Make, чтобы не чинить «вслепую».

Чем IndexNow отличается от обычного ping/RPC?

Классический ping sitemap – устаревший сигнал «обновите карту». IndexNow передаёт конкретный список URL с проверкой ключа и официально поддержан Яндексом и другими участниками. Workflow современнее и прозрачнее по кодам ответа.

Закроет ли один POST и Google?

Нет. В 2026 Google IndexNow не принимает. Для Google оставьте sitemap и Search Console. Не делайте вывод «пинговал – значит везде проиндексировали».
