Чтобы cursor agent сам писал бриф по утрам, откройте cursor.com/automations/new, создайте одно задание Automations с расписанием, не подключайте репозиторий GitHub, задайте короткий промпт на один текст и сразу сделайте пробный запуск – готовый бриф или черновик появится в истории прогонов.

Когда Automations по расписанию не брать

Если задача разовая и вы у ноутбука – обычный чат дешевле. Если нужен ответ на заявку "прямо сейчас" – смотрите webhook, не cron. Боль утра – снова писать бриф руками, потому что не сделали Test run. Типичная ошибка: повесить GitHub и Max Mode "на всякий" в первый вечер. На практике одна Automation, короткий промпт, успешный пробный прогон.

GitHub Actions, SDK и сравнение режимов Cursor на этот вечер не нужны. Достаточно одного таймера и одного проверяемого результата: успешный пробный прогон с понятным текстом в ответе.

Представьте утро без ручного брифа: вы открываете историю Automation и видите готовый текст. Если этого файла нет – вернитесь к Test run. Из практики чаще ломается часовой пояс и слишком длинный промпт, а не "магия cron".

Получилось = задание Automations сохранено с расписанием, в истории есть успешный пробный прогон, в ответе лежит бриф, дайджест или черновик поста. Не получилось = вы снова пишете вручную в обычном чате или ждёте "боевое" утро без пробного прогона.

Чем Automations отличается от чата и кнопки Cloud Agent

В Cursor легко перепутать три похожие кнопки. Обычный чат Agent mode – это "напиши сейчас, пока я смотрю". Кнопка Cloud Agent – разовый запуск в облаке, тоже руками. Automations – задание, которое стартует само по расписанию или событию.

Если цель – утренний бриф без ручного старта, нужен третий вариант: Automations и триггер Scheduled. Scheduled – это расписание: либо готовый preset вроде "каждый день", либо строка cron. Cron – компактная запись времени; в Cursor по умолчанию она идёт в UTC, поэтому "9:00" без пояснения часового пояса часто приедет со сдвигом.

Я бы не тратил вечер на разбор Slack, webhook (входящий сигнал из другого сервиса) и GitHub. Сначала один таймер и один текст. Остальное – когда уже есть успешный прогон в истории.

Что подготовить до кликов

Нужен аккаунт Cursor с доступом к Cloud Agents – обычно это платный план. Откройте браузер на cursor.com/automations или Agents Window в самом Cursor. Репозиторий GitHub для текстового брифа не обязателен. Канон шагов – в docs Cursor Automations.

Сформулируйте одну задачу одной фразой, например: "Напиши утренний бриф по нише X в markdown: 5 пунктов, один угол для поста, без воды". Критерий готовности должен быть в промпте: что именно считается готовым файлом или ответом. Без этого агент легко раздует ответ и сожжёт usage – расход по тарифу облака.

Automations анонсировали 5 марта 2026: агент может работать по расписанию и событиям. Для маркетинга за вечер хватает узкого куска – weekly или daily digest, как в официальных примерах, только без обязательного Slack и без правок кода.

Создаём одну Automation с расписанием

  1. Откройте cursor.com/automations/new.
  2. В триггере выберите Scheduled. Для первого раза удобнее взять preset "каждый день" или "каждую неделю". Если нужен cron – см. следующий раздел про UTC.
  3. Вставьте узкий промпт: тема, формат markdown, длина, что не делать (не искать репозиторий, не открывать PR, не ходить по лишним инструментам).
  4. Tools оставьте минимальными. Широкий набор MCP – внешних подключений к сервисам – и секретов здесь лишний.
  5. В scope репозитория выберите No repository – без репозитория. Без явного repo агент не клонирует код и не откроет pull request: так в документации для Slack и cron без правок кода.
  6. Сохраните и активируйте Automation.

Community-пример для понедельника 09:00 UTC выглядит как 0 9 * * 1. Для Москвы без префикса часового пояса это будет не "девять утра у вас", а девять по UTC. Поэтому либо preset, либо cron с явным поясом.

Позиция простая: для первого брифа No repository – правильный выбор. Репозиторий подключайте только когда реально нужен файл в git или PR. Иначе вы тащите страх "сломаю код" туда, где нужен обычный текст.

UTC, CRON_TZ и почему "9:00" врёт

Cron в Automations по умолчанию в UTC. Чтобы получить локальное время, в начало строки ставят префикс вида CRON_TZ=Europe/Moscow 0 9 * * 1-5 – будни в 09:00 по Москве. На форуме Cursor сотрудник продукта прямо писал: даже внутренние разработчики путаются в этом UI. Это не ваша "нетехничность", это сырой cron без человеческой подписи.

Ещё одна ловушка: если вы уже сохранили Automation и потом меняли расписание с daily на weekly, сервер иногда не применял новую схему. Workaround из треда форума – удалить Automation и создать заново, а не крутить тумблеры бесконечно.

Я бы не ждал первого "боевого" утра, чтобы понять сдвиг. Сначала пробный запуск, потом уже верить будильнику.

Test run: что нажать и что считать победой

После Save и Activate найдите Test run – кнопку пробного запуска – и запустите сразу. Дождитесь статуса в history Automations, то есть в истории запусков. Откройте прогон и сохраните ответ или файл: бриф, дайджест, черновик поста – любой понятный текст по вашему критерию.

Документация предупреждает: прогон по расписанию может задержаться, но не стартует раньше указанного времени. Поэтому Test run важнее "подождать до утра". Утренний слот проверяете уже после того, как текст в истории выглядит нормально.

Если в ответе каша, укоротите промпт и уберите лишние tools. Если прогон пустой или ошибка доступа – проверьте, что Automation активна, план поддерживает Cloud Agents, и вы не ждёте репозиторий там, где выбрали No repository.

Что видите Что это значит Что сделать
Successful run + связный markdown Первый результат есть Оставить Scheduled, не трогать webhook
Текст есть, но не вовремя Скорее UTC без CRON_TZ Preset или префикс Europe/Moscow, затем снова Test run
Долгий или дорогой прогон Широкий промпт и дорогая модель Сузить задачу, выбрать более дешёвую модель из пула Cursor, смотреть usage
Расписание "не то" после правки daily→weekly Известный баг применения schedule Создать Automation заново с нуля

Деньги, Max Mode и что не включать сегодня

Cloud Agents и Automations работают в Max Mode – режиме полной мощности модели; в Automations он включён всегда. Биллинг идёт как cloud/API usage выбранной модели – это не "бесплатная кнопка в редакторе". Отдельного лимита "не дороже N рублей за один прогон" в UI Automations на момент проверки форума не было: есть месячные лимиты и ручная отмена. Поэтому hourly-cron и расплывчатый промпт – быстрый способ сжечь бюджет.

Я бы не ставил "каждый час" "на всякий случай". Один утренний слот и узкий артефакт. Permissions (Private / Team Visible / Team Owned) влияют и на доступ коллег, и на чей usage pool списывается – для личного брифа держите Private, пока не нужна команда.

Не делайте в тот же вечер: webhook POST, RSS→Telegram, установку Junior или роя агентов, локальный SDK-скрипт. Это соседние задачи. Сначала текст в истории от одной Scheduled Automation.

Частые вопросы

Нужен ли GitHub, чтобы получить бриф?

Нет. Для текста выберите No repository: агент не клонирует код и не откроет PR. Репозиторий нужен, когда цель – правки в git, а не утренний markdown.

Почему прогон пришёл не в "мои" 9:00?

Cron Automations по умолчанию в UTC. Добавьте CRON_TZ=Europe/Moscow … или возьмите preset, затем проверьте Test run до боевого утра.

Можно ли сразу повесить webhook или RSS→Telegram?

Можно технически, но это другой вечер. Сначала одна Scheduled Automation и артефакт в истории – иначе вы чините три системы сразу.

Automations сожгут весь бюджет?

Риск есть: Max Mode включён, лимита стоимости одного прогона в UI нет. Узкий промпт, редкий слот, контроль usage dashboard – обязательная гигиена, не опция.

Что считать успехом Test run?

Automation сохранена с расписанием, в истории есть успешный пробный прогон, в ответе лежит бриф или черновик. Пустой прогон "без текста" – ещё не готово. На практике не ждите "боевое утро" без этой проверки.

Нужен ли Max Mode в первый вечер?

Automations идут в Max Mode по модели продукта – выключить нельзя. Поэтому сегодня короткий промпт и один артефакт, без зоопарка интеграций. Иначе быстро и дорого сожжёте лимит на пустых циклах.
