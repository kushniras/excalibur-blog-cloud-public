Снова открываете чат в Cursor и пишете одно и то же: «по-русски, без канцелярита, ключи в ответ не вставляй». Агент то кивает, то забывает через три сообщения — и вы снова копируете простыню из заметок. На это уходит время, а тон всё равно плывёт.

Если сделаете одно короткое постоянное правило на 5–10 строк и один навык, который зовёте через /, к вечеру можно проверить результат: новый чат сам держит тон без напоминания, а бриф поста поднимается по команде — без копипаста из заметок.

Две полки: что всегда, что по задаче

В Cursor две разные полки. Правила проекта лежат в папке .cursor/rules/ как файлы .mdc. В начале файла — короткая шапка (frontmatter): если там alwaysApply: true, текст правила попадает в каждый чат. Это «табличка на двери». Обычный .md без такой шапки система правил может просто проигнорировать.

Навык (Skill) — другая полка: папка с файлом SKILL.md в .cursor/skills/. Его подключают по описанию или когда вы пишете /имя в Agent-чате. Официальная справка формулирует просто: Rules — короткие ограничения, Skills — пошаговые сценарии. На первый вечер хватит одного Always Apply и одного Skill по /. Остальные режимы (по файлам, вручную через @) подождут.

Практический фильтр: если без этой фразы любой ответ будет кривым — alwaysApply. Если это чек-лист конкретной задачи — Skill. «Пиши по-русски, без канцелярита, не свети ключи» — всегда. «Собери бриф: цель, аудитория, оффер, запреты» — по запросу. Я бы начал именно с этой развилки, а не с плагинов и не с MCP (это отдельные подключения инструментов к агенту).

Любопытный факт из документации: команда /migrate-to-skills (с Cursor 2.4) переносит только «динамические» правила без alwaysApply и без привязки к путям файлов. Вечные договорённости специально оставляют правилами, а не скиллами.

Шаг 1. Одна договорённость на 5–10 строк

Выберите одну связку на сегодня — не пять. Для маркетинга обычно хватает: язык ответов, тон без канцелярита, запрет секретов и ключей в чат. Всё остальное подождёт.

  1. Откройте папку проекта в Cursor — лендинг, брифы, тексты, что угодно.
  2. Создайте файл вроде .cursor/rules/brand-voice.mdc. Имя любое, путь важен.
  3. В шапке поставьте alwaysApply: true. Ниже — 5–10 строк обычным текстом, без чек-листа поста.
  4. Либо в Agent-чате наберите /create-rule, либо откройте Customize → Rules и выберите Always Apply.

Пример тела правила — коротко:

  • отвечай по-русски, без канцелярита;
  • не выдумывай цифры и кейсы;
  • не проси и не повторяй API-ключи, пароли, токены.

После сохранения зайдите в Customize → Rules: должно быть видно одно Always Apply, текст короткий. Длинный runbook «как писать бриф» сюда не кладите. Документация советует держать rules короче 500 строк и начинать просто — добавлять пункты, когда агент реально повторяет одну и ту же ошибку.

На практике community-аудит «alwaysApply tax» нашёл у команды около 22 always-on правил — примерно 2700 строк в каждом запросе, вплоть до ответа на «сколько будет 2+2». Hexlet прямо пишет: alwaysApply на всё жрёт контекст. Вам сегодня нужна одна табличка, не стена.

Если уже насоздавали несколько Always Apply «на всякий случай» — оставьте одно короткое, остальные снимите с Always Apply или перенесите процедуры в Skill. Recovery здесь не «добавить шестое правило», а урезать налог.

Проверка: новый чат без ритуала тона

Откройте новый чат. Не вставляйте старый промпт про тон. Попросите короткий абзац для Telegram или уточните «что нельзя писать в ответ». Если агент сам держит язык, тон и запрет секретов — правило работает. Это и есть первый результат: вы перестаёте тратить время на копипаст.

Загляните в Customize → Rules ещё раз. Если файла нет или путь странный — стоп. На форуме Cursor часть аккаунтов жалуется: кнопка New Rule иногда создаёт SKILL.md вместо .cursor/rules/*.mdc. Тогда правило и навык путаются местами.

Проверка пути без магии:

  • правило — .cursor/rules/что-то.mdc с шапкой alwaysApply;
  • skill — .cursor/skills/имя-папки/SKILL.md;
  • plain .md в rules без шапки система может игнорировать.

При сомнении пересоздайте через /create-rule отдельно от /create-skill, затем снова откройте Customize → Rules и Customize → Skills.

Если тон всё ещё плывёт, не дописывайте сразу второе alwaysApply. Сократите первое: уберите примеры и чек-листы «на всякий случай». Оставьте язык, тон и запрет секретов. Честно говоря, многие останавливаются на «файл лежит» и не открывают новый чат — без этой проверки иллюзия настройки остаётся, а рутина возвращается.

Шаг 2. Один Skill на бриф поста

Когда постоянный тон уже держится, вынесите повторяемый сценарий в Skill. Создайте папку .cursor/skills/post-brief/ и внутри SKILL.md. В шапке нужны name и description — коротко, когда звать навык. В теле — шаги брифа: цель, аудитория, оффер, запреты, длина, канал. Не разворачивайте здесь дизайн-офис: один сценарий, который вы реально повторяете каждую неделю.

  1. Создайте структуру руками или через /create-skill в Agent-чате.
  2. Проверьте путь: файл лежит в .cursor/skills/…/SKILL.md, не в rules.
  3. В Agent наберите /post-brief (или имя папки).
  4. Откройте Customize → Skills: навык должен быть в списке.

Что увидеть после создания: в Customize → Skills виден ваш навык; по /имя агент проходит чек-лист брифа, а не просит снова скопировать промпт из заметок. Description пишите так, чтобы было ясно, когда навык уместен — иначе он либо молчит, либо лезет не в ту задачу.

Если skill «не находится» — проверьте путь и description, пересоздайте через /create-skill. Если оба файла оказались в одной папке — разнесите по полкам rules и skills. Шаги навыка не копируйте обратно в alwaysApply: иначе снова получите простыню в каждом «привет». Skill — рецепт по задаче; правило — то, без чего нельзя отвечать вообще.

Как понять, что получилось

Короткий критерий на вечер:

  1. в .cursor/rules/ лежит одно короткое .mdc с alwaysApply: true;
  2. в .cursor/skills/ — один SKILL.md с понятным description;
  3. новый чат сам держит тон без напоминания;
  4. по /имя-скилла отрабатывает бриф поста;
  5. в Customize видны оба артефакта; шаги навыка не продублированы в правиле.

Откройте новый чат, напишите задачу без промпта про тон, затем вызовите skill брифа. Если оба шага спокойные — настройка Cursor для вашей задачи уже дала результат: меньше рутины и быстрее повтор сценария.

Типичная ошибка — повесить на Always Apply всё, «чтобы агент был умнее». Умнее он не становится: контекст забит, ответы тяжелее. Вторая — ждать плагин или MCP до первой пары файлов: для маркетолога сегодня достаточно аккаунта Cursor и папки проекта. Третья — дублировать один и тот же чек-лист и в правиле, и в skill: правьте в одном месте.

Когда базовая пара уже работает, можно углубиться: разбор настройки правил проекта, подборка маркетинговых skills, учебный маршрут Rules → Skills в публичном Cursor Jr. SEO+GEO skill и роли субагентов — следующий слой, не входной билет.

Частые вопросы

Чем правило отличается от Skill?

Правило — короткая договорённость и ограничения. Skill — пошаговый сценарий, который подключаете по задаче через / или по description.

Нужно ли вешать alwaysApply на каждый файл инструкции?

Нет. Always Apply только на то, что должно быть в каждом чате. Длинные процедуры держите в Skill, иначе раздуете контекст.

С чего начать настройку Cursor, если уже открыт Agent-чат?

С одной короткой alwaysApply-договорённости и проверки в новом чате. Затем один Skill на ваш частый сценарий — например бриф поста.

Можно ли совместить правило и Skill в одном проекте?

Да, так и задумано: постоянный тон в .mdc, повторяемый чек-лист в SKILL.md. Главное — не копировать шаги навыка в alwaysApply.

Почему New Rule создал SKILL.md не туда?

У части аккаунтов так бывает по отчётам форума Cursor. Проверьте путь: правило — .cursor/rules/*.mdc, skill — .cursor/skills/…/SKILL.md. При путанице пересоздайте через /create-rule и /create-skill.

Что делать, если уже насоздавали много Always Apply?

Оставьте одно короткое (язык, тон, запрет секретов), остальное снимите с Always Apply или перенесите процедуры в Skill. Не добавляйте ещё одно «на всякий случай».

Это то же самое, что плагин или MCP?

Нет. Правила и skills — встроенная настройка поведения агента в проекте. Плагины и MCP — отдельный слой; их имеет смысл смотреть после рабочей пары файлов.
