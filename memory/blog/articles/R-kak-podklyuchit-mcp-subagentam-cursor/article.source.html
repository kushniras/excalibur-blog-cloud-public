Вы уже собрали оркестратор и роли после гайда про субагентов. В Cursor MCP (это подключенный сервер инструментов для агента) в Tools зелёный. Просите Researcher «собери спрос по нише» — а в brief.md снова «примерно 10 тысяч показов». Цифры копируете из вкладки Wordstat, картинки — из другой: рутина не исчезла. Параллельно Designer не опишет картинку словами вместо файла, пока у роли нет живого image-tool.

Ниже спокойный маршрут «делай вместе со мной». Цель не «подключить ещё сервер», а назначить уже зелёный MCP одной роли: один tool, один успешный вызов и живые данные в handoff (это короткий файл-передача между ролями). Так вы сэкономите время на ручном копировании частотностей и ассетов.

За один прогон одной роли — Researcher к Wordstat или Designer к image MCP — в чате виден успешный tool call, в handoff лежит число показов или URL картинки, секреты не в тексте роли, day-1 активен только один сервер.

Путь по порядку: выбрать роль → оставить один MCP → проверить секреты → прописать tool в agent.md → прогнать оркестратор→роль→файл. Если сервер ещё красный или mcp.json пустой, сначала подключение MCP в Cursor. Если ролей ещё нет — офис с оркестратором и handoff. Эта статья — слой поверх: розетка уже есть, нужно воткнуть прибор в одну роль.

Выберите одну роль на сегодня: Researcher или Designer

Две рабочие ветки day-1. Researcher тянет живые частотности через Wordstat MCP (как в пакете Ядрышко). Designer тянет картинку через image MCP (как в AURA). Сегодня нужна одна ветка, не обе.

  1. Откройте заметку на вечер и напишите одну фразу: «сегодня только Researcher» или «сегодня только Designer».
  2. Рядом укажите артефакт: «число показов в brief.md» или «URL/путь картинки в handoff».
  3. Откройте файл роли в проекте: .cursor/agents/ — research.md или designer.md.
  4. Вторую роль не трогайте и не давайте ей tool «на всякий случай»; задание одно — спрос по нише или один визуал, не «весь контент-план».

Проверка: в заметке одна роль и один критерий файла. Второе имя роли отсутствует.

Ошибка и восстановление: если снова хочется «и цифры, и обложку» — оставьте Researcher→Wordstat. Designer перенесите на следующий спокойный прогон. Две ветки в один вечер раздувают список tools и возвращают к копипасту. Если файла роли ещё нет, сначала закройте слой ролей в гайде про оркестратор — иначе некуда прописать имя tool.

Оставьте включённым один MCP, остальное выключите

По документации Cursor субагенты наследуют все MCP-инструменты родителя. Отдельного whitelist «только Wordstat для Researcher» в frontmatter (это шапка файла роли) пока нет — так пишут docs и staff на форуме Cursor. Назначить tool роли на практике значит: сузить список серверов и явно написать вызов в инструкции.

  1. Откройте Cursor → Settings → Tools & MCP.
  2. Найдите MCP-KV (или ваш image-сервер) — он должен быть зелёным.
  3. Остальные серверы выключите toggle (это переключатель On/Off без удаления конфига) — без «ещё четырёх полезных MCP» в тот же вечер.
  4. Вернитесь в чат Agent и убедитесь, что в списке tools виден один нужный набор.

Проверка: в Tools активен один сервер под выбранную роль; соседние Off.

Ошибка и восстановление: типичная ошибка day-1 — зоопарк из пяти серверов. Если субагент падает с resource_exhausted (это отказ из‑за перегруза контекста tools) — сначала выключите лишние серверы, не пересоздавайте роли. Community на форуме Cursor как раз ловит этот сбой.

Проверьте зелёный статус и спрячьте секреты

Для Researcher откройте документацию Wordstat MCP-KV: API Key (это ключ доступа к сервису), Folder ID и роль search-api.webSearch.user. Для Designer — один image-tool по инструкции вашего сервера. Секреты живут в dashboard MCP-KV или в переменных окружения через запись вида env в mcp.json — не в тексте agent.md и не в чате.

  1. В dashboard MCP-KV нажмите «Проверить и сохранить» после ключа и Folder ID.
  2. Дождитесь зелёного статуса сервера в Cursor → Tools & MCP.
  3. Откройте agent.md выбранной роли и поищите по файлу слова key, token, secret.
  4. Если ключ лежит в промпте — вырежьте, перенесите в dashboard или env и сохраните файл роли без секретов.

Проверка: сервер зелёный; в agent.md нет ключей; в чате вы не вставляли токен «для скорости».

Ошибка и восстановление: ответ 401 или 403 — перепроверьте ключ и роль search-api.webSearch.user. Ответ 429 — пауза и повтор, не новый сервер. Красный статус при «правильном» ключе — вернитесь к гайду про подключение MCP, не правьте ownership ролей вслепую.

Пропишите имя tool и критерий артефакта в agent.md

Пока в инструкции роли нет имени tool и правила «не угадывать», зелёный сервер в Settings не помогает: роль ходит мимо него. Без живого Wordstat частотности не подтверждены; без image-tool картинка снова «в голове» у модели.

  1. Откройте .cursor/agents/research.md (или designer.md).
  2. Добавьте строку действия: например «вызови wordstat_get_top_requests» или имя вашего image-tool.
  3. Добавьте критерий: «в handoff/brief только живое число показов» или «только URL/путь файла картинки».
  4. Запретите угадывание: «не пиши «примерно N», если tool не вызывался».
  5. Сохраните файл. Оркестратору в его agent.md можно коротко напомнить: «Researcher без успешного Wordstat-вызова не считается готовым».

Проверка: в тексте роли есть имя tool и критерий артефакта; запрет «примерно» на месте.

Ошибка и восстановление: роль снова выдаёт оценки без вызова — не подключайте второй MCP. Допишите имя tool и критерий файла. Ожидание официального per-tool whitelist в frontmatter сегодня не сработает: staff Cursor подтвердил, что такого scope пока нет; флаг readonly режет MCP целиком.

Прогоните оркестратор → роль → файл в handoff

Теперь один чистый цикл в IDE. Cloud Agents (это облачный прогон на cursor.com/agents) берут MCP из team-конфига на dashboard, не из вашего локального mcp.json — day-1 остаёмся в локальном Agent.

  1. Откройте Agent в Cursor в корне проекта.
  2. Попросите оркестратора делегировать задачу выбранной роли одной фразой: «собери спрос по [ниша] через Wordstat» или «сделай один визуал через image MCP».
  3. Дождитесь, пока роль реально вызовет tool — в чате должен появиться успешный MCP tool call, не абзац «примерно».
  4. Проверьте handoff: файл с числом показов или с URL/путём картинки.
  5. Если есть Reviewer — пусть сверит: в файле есть цифра/URL, совпадающие с ответом tool.
  6. Не запускайте параллельно вторую роль на тот же brief.

Проверка: в чате роли виден успешный вызов; в handoff лежит живой артефакт; копипаст из вкладки Wordstat или Midjourney не понадобился. Сверьте: число в файле совпадает с ответом tool, а не с «оценкой модели».

Ошибка и восстановление: tool не вызвался — вернитесь к toggle (один сервер) и к формулировке в agent.md. Если правите Cloud Agent и «не видит» локальный mcp.json — это ожидаемо; сначала закройте локальный прогон. Пустой handoff при «успешном» тексте в чате — роль не выполнила критерий артефакта: повторите шаг с явным «положи число/URL в файл handoff». Если роль описала картинку словами вместо файла — снова Designer + image-tool, не новый текстовый промпт «нарисуй в голове».

Вечером: живые данные вместо «примерно»

Утром MCP был зелёный, а brief снова врал «примерно». Результат маршрута: у одной роли видимый успешный tool call и файл с живыми данными — рутина вкладок на этом задании снята. Зоопарк из пяти серверов и Team MCP для Cloud — не сегодняшний слой.

Когда первый вызов стабилен, можно вырастить тот же паттерн: семантическое ядро через Wordstat, картинки через MCP, подбор ключей. Базовый офис без tool — в гайде про субагентов; плагины и skills — в плагинах и skills.

Частые вопросы

Что такое MCP сервер простыми словами?

Это отдельная программа-розетка: агент через неё дергает внешний сервис (Wordstat, генерацию картинок и т. п.), а не выдумывает ответ. «Настройка mcp сервера» для новичка чаще всего = зелёный статус в Tools + ключ вне промпта, без своего Nginx.

Нужна ли отдельная настройка MCP на каждую роль?

Отдельного официального whitelist на роль нет: роли видят tools родителя. Практический обход — один активный сервер day-1 и явная инструкция tool в agent.md нужной роли.

Хватит ли бесплатных MCP серверов?

Для первого успеха достаточно одного рабочего (MCP-KV Wordstat или один image). Каталог «список mcp серверов» и «бесплатные mcp сервера» не ускоряют вечер, если роль всё ещё пишет «примерно».

Зачем MCP, если роли уже есть?

Роли делят работу и файлы. Без живого tool офис снова копирует цифры и картинки из вкладок.

Почему не настраивать сразу Cloud Agents?

Локальный mcp.json не подхватывается Cloud Agents автоматически — нужен Team MCP. Сначала закройте локальный прогон с артефактом в handoff, потом переносите конфиг в облако команды.
