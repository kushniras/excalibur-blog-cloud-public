Если непонятно, куда в Cursor положить плагин Excalibur, и страшно сразу выкладывать текст в WordPress — маршрут такой: скачать репозиторий с GitHub, подключить через Customize или папку локальных плагинов, сделать Reload Window, запустить прогон с publish: no и проверить, что в папке темы появились research-notes и черновик. На сайт ничего не уходит, пока вы сами не разрешите публикацию.

Это не «ТОП-15 нейросетей для блога» и не простыня из одного Composer «напиши статью на 3000 знаков». Роли идут по очереди: research сначала кладёт факты в файл, потом пишется черновик. Публикация — только после того, как вы открыли файлы и прочитали текст.

Критерий готово: команда /excalibur-blog-run … publish: no (или явная фраза «без публикации») дала папку темы с research-notes.md и черновиком / article.html; роли не перетирают чужие файлы; в WordPress ничего не ушло.

Что ставите и чем это не рейтинг SaaS

Excalibur — публичный Cursor-плагин автоблога из репозитория Horosheff/EXCALIBUR (на 2026-07-23: ★23, последний push 2026-06-11, ветка master). В манифесте plugin.json имя excalibur-blog, версия 0.2.1: подключаются rules, skills, agents и commands.

Плагин — это папка с инструкциями, которую Cursor подхватывает после перезагрузки окна. Субагент — отдельная роль со своим контекстом (research, черновик, проверка), а не «ещё один промпт в том же чате». Рой здесь значит несколько таких ролей вместо одного Composer «напиши статью на 3000 знаков».

В выдаче по «ии для блога» почти сплошь рейтинги сервисов. Готовый how-to установки роя в Cursor почти не разобран. Я бы не начинал со сравнения Jasper и подписок за $150/мес: сначала один плагин и один сухой прогон до файлов.

Анонс в канале: пост про Excalibur — GitHub и порядка десяти субагентов. Разбор «зачем рой вместо одного агента» — в посте про рои; саммит смотреть не обязательно.

Шаг 1. Две вкладки GitHub

Откройте канон: github.com/Horosheff/EXCALIBUR. Параллельно держите Horosheff/excalibur-blog-cloud-public (★16): там полный README быстрого старта. В самом EXCALIBUR README на raw часто нет — новичок без второй вкладки застревает на пустой главной.

Скачайте архив или клонируйте репозиторий плагина. Цель — локальная копия с .cursor-plugin и каталогами agents, skills, commands. Секреты WordPress и ключи в чат не пишите: для первого прогона они не нужны.

Шаг 2. Куда положить плагин

По документации Cursor Plugins есть два рабочих пути:

  • подключить плагин через страницу Customize в Cursor;
  • положить копию в локальную папку плагинов: обычно ~/.cursor/plugins/local/excalibur-blog (или путь из README cloud-public, если он указан иначе).

Имя папки лучше совпасть с name из plugin.json — excalibur-blog. Не раскладывайте файлы «куда попало» по корню проекта сайта: плагин живёт в зоне plugins Cursor, а статья потом появится в папке темы блога.

Я бы не ставил рядом Hyperion, TEYA, AURA или офис веб-страниц «на всякий случай». Один рой — один критерий готовности. Соседние install-рои — после того, как этот dry-run дал файлы.

Шаг 3. Reload и проверка, что агенты видны

В Cursor: Developer → Reload Window (или Restart, как в вашей версии). После перезагрузки откройте Customize / список агентов и команд.

Критерий «плагин встал»:

  • виден Excalibur / excalibur-blog;
  • или в дереве проекта/плагина видны файлы .cursor/agents/ из поставки.

Кастомные субагенты Cursor живут в .cursor/agents/ и работают с отдельным контекстом — так описано в доках Subagents. Если после Reload пусто: проверьте путь local, имя папки, что манифест .cursor-plugin/plugin.json на месте, снова Reload. Не гоните команду запуска, пока агенты не видны — получите хаос в чате, а не рой.

Шаг 4. Одна ниша и команда с publish: no

Подготовьте отдельную папку проекта под один сайт или одну нишу. Выберите одну тему — не план на квартал.

Команда запуска в плагине: /excalibur-blog-run. Важно: по умолчанию в commands/excalibur-blog-run.md стоит publish: yes. Для первого прогона явно пишите publish: no (или фразу «без публикации»). Пример смысла запроса: /excalibur-blog-run topic_id: одна-тема publish: no.

Dry-run здесь — прогон пайплайна без выкладки на сайт. Секреты, если позже понадобятся, только в Dashboard / переменных окружения, не в переписке с агентом.

Я бы не обещал WordPress «сразу после установки». Сначала файлы и ручной просмотр. Publish + перелинковка + Cloud Automations 24/7 — следующий контур, не цель установки.

Шаг 5. Что проверить, когда прогон закончился

Откройте папку темы вида memory/blog/articles/<topic>-…/ и найдите:

  1. research-notes.md — бриф с фактами и источниками, не вода из одного ответа чата;
  2. черновик или article.html — текст статьи после ролей, а не сырой dump Composer.

Дополнительно: роли не должны перетирать чужие файлы посередине прогона; в админке WordPress новых постов от этого прогона быть не должно.

Получилось за вечер, если одновременно: после Reload виден Excalibur, команда с publish: no отработала, research-notes и черновик лежат локально, WordPress пуст. Не получилось = нет папки темы, нет research-notes, или плагин так и не появился после Reload — возвращайтесь к шагам 2–3, не к «ещё одному промпту напиши статью».

Частые вопросы

Нужен ли доступ к WordPress в первый прогон?

Нет. Цель — локальные research-notes и черновик при publish: no. Доступ к сайту подключайте после ручной проверки текста.

Почему две ссылки на GitHub?

EXCALIBUR — канон плагина из анонса. excalibur-blog-cloud-public даёт читаемый README быстрого старта, когда в каноне README нет.

Чем это лучше одного чата «напиши статью»?

Роли разделены: research собирает факты в файл, затем пишется черновик. Один Composer смешивает всё в одном контексте и чаще выдаёт воду без источников — это как раз боль, из которой люди ищут «ии для блога».

Можно ли сразу поставить Ядрышко или офис страниц?

Технически да, практически я бы не стал: смешаете критерий «готово» и отладку. Сначала один dry-run Excalibur до файлов статьи.

Это только для программистов?

Маршрут тот же, что у других готовых плагинов Cursor: скачать → положить → Reload → одна команда. Код с нуля писать не нужно. Нужны Cursor, GitHub и готовность проверить папку с файлами.
