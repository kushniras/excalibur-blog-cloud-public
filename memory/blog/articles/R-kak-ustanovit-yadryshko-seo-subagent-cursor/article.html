Поставьте Ядрышко в Cursor с живым Wordstat (это цифры показов Яндекса) и получите папку с кластерами запросов, картой страниц и брифами – не список ключей "примерно по 5–10 тысяч" из чата. Так меньше пустых URL и больше шанс на трафик и заявки с нужных страниц.

Когда Ядрышко ставить не сейчас

Если Wordstat в Tools & MCP ещё красный – сначала один зелёный тест цифры, не /core. Если нужна "просто идея для поста" без карты URL – хватит короткого research в чате. Типичная ошибка: просить чат "ключи под услуги" без проверки показов и через месяц ловить пустые статьи.

Не путайте Ядрышко с генератором готовых текстов "под ключ". Результат пакета: кластеры, url-map и брифы с живыми цифрами Wordstat – не фантазия из чата.

Критерий "получилось": в проекте есть .cursor/agents/core.md (или виден /core после Reload Window); в Settings → Tools & MCP сервер Wordstat зелёный и тестовый wordstat_get_top_requests вернул цифру; в research/semantic-core-runs/<сайт>-<дата>/ лежат 05-clusters.csv, 06-url-map.csv, 07-content-briefs.md (не меньше трёх брифов) и index.html; частотности живые либо честно "не подтверждены".

Что нужно до первой команды

Нужны Cursor, аккаунт Яндекса с API Key и Folder ID, роль search-api.webSearch.user и доступ к GitHub, чтобы скачать install. Если папки .cursor в проекте ещё нет – она появится после установки. Секреты держите в dashboard или env, не вставляйте в чат агента.

Подключить Wordstat в MCP-KV

Линейный маршрут до первого пакета – чтобы не застрять между MCP и плагином:

  1. Подключите Wordstat в MCP-KV по гайду проекта; сохраните секреты вне чата.
  2. В Settings → Tools & MCP дождитесь зелёного статуса и запросите одну тестовую цифру показов.
  3. Установите Ядрышко (плагин/роль core) и сделайте Reload Window при необходимости.
  4. Вызовите /core с URL сайта и регионом; дождитесь файлов пакета в проекте.
  5. Откройте кластеры, url-map и брифы: сверьте, что цифры Wordstat не "примерно", а из MCP.
  6. Не пишите сразу 20 статей – выберите 1–2 URL из карты на завтра.

На практике часто ломается порядок: ставят Ядрышко до зелёного Wordstat и решают, что "ИИ для SEO не работает". Сначала цифра в MCP, потом /core.

MCP – это способ дать Cursor доступ к внешнему инструменту. Откройте гайд mcp-kv.ru/docs/wordstat-mcp-setup. В кабинете MCP-KV укажите API Key из AI Studio Яндекса, Folder ID из раздела folders (не ID всего облака) и роль search-api.webSearch.user.

Нажмите "Проверить и сохранить". Если сервис отвечает 401 – битый ключ. 403 – чаще биллинг, карта или нет нужной роли. 429 – упёрлись в квоту Search API. Пока тест не проходит, ставить Ядрышко рано: без живых цифр снова получите "примерно".

Проверить зелёный Tools & MCP и одну цифру

В Cursor откройте Settings → Tools & MCP. Сервер MCP-KV / Wordstat должен быть зелёным. Сделайте один тестовый вызов wordstat_get_top_requests по parent-фразе вашей ниши – например по "семантическое ядро" или по услуге сайта. Нужна любая реальная цифра показов, не "модель прикинула".

Для ориентира на дату 2026-07-22 по России (регион 225): "ии для seo" – 168 показов в месяц, "нейросети для seo" – 74, parent "семантическое ядро" – 4107. Эти числа из Wordstat MCP, не из головы. Если тест вернул цифру – можно ставить Core. Если нет – чините доступы, не подключайте "ещё пять инструментов на всякий случай".

Установить Ядрышко одной командой

Субагент здесь – готовая роль в Cursor: файл инструкции, которую вызывают по слешу. Ядрышко ставится в корень проекта одной командой и появляется как /core. Репозиторий публичный: Horosheff/yadryshko-semantic-core-subagent.

На macOS/Linux:

curl -fsSL https://raw.githubusercontent.com/Horosheff/yadryshko-semantic-core-subagent/main/install.sh | bash

На Windows (PowerShell):

irm https://raw.githubusercontent.com/Horosheff/yadryshko-semantic-core-subagent/main/install.ps1 | iex

После команды проверьте файл .cursor/agents/core.md. Рядом могут лечь docs, scripts и templates – это нормально. Затем Reload Window в Cursor, чтобы роль /core стала видна. По документации Cursor субагенты наследуют инструменты родителя: зелёный Wordstat у вас в проекте означает, что /core сможет дергать те же tools.

Не ставьте сейчас AURA, SEO-skill и пачку соседних подключений. Цель – один SEO-агент и один прогон.

Вызвать /core с URL и регионом

В чате Cursor вызовите /core и передайте адрес сайта (или нишу), регион – например Россия / 225 – и цель: заявки или трафик. Формат из README: /core, URL вроде https://example.ru, регион. Дождитесь окончания прогона.

Результат лежит в research/semantic-core-runs/<сайт>-<дата>/. Имена папки и файлов смотрите в проводнике проекта, не в пересказе чата.

Открыть пакет файлов – критерий "готово"

Минимум пакета файлов за вечер, без которого прогон не закрыт:

  • 05-clusters.csv – группы запросов;
  • 06-url-map.csv – какие страницы писать под спрос;
  • 07-content-briefs.md – не меньше трёх брифов под конкретные URL;
  • index.html – сводный отчёт.

Частотности в отчёте либо живые (из Wordstat), либо явно "не подтверждены". Выдуманные показы "примерно" – провал, даже если CSV красивый. Google в AI-optimization guide прямо пишет: для генеративных фич поиска по-прежнему нужно обычное SEO, а не отдельный "GEO-хак". Карта спроса и нормальные страницы важнее рейтинга "лучших ИИ для SEO".

Получилось = четыре пункта выше на диске. Не получилось = нет core.md, MCP красный, тест Wordstat без цифры или в папке нет CSV/HTML.

Типичные сбои на линейном маршруте

Симптом Что проверить Что сделать
/core не виден Есть ли .cursor/agents/core.md Переустановить install, Reload Window
MCP зелёный, цифры "примерно" Тест wordstat_get_top_requests, роль, Folder ID Починить доступ; не гонять /core "наугад"

Отдельно: рейтинг Surfer/Jasper/ChatGPT из выдачи "лучшие ИИ для SEO" не заменяет этот маршрут. Генератор текста пишет абзацы. Ядрышко отвечает на вопрос, о каких страницах писать под живой спрос.

Что делать после пакета – и чего не делать сегодня

На практике возьмите один бриф из 07-content-briefs.md и одну строку из 06-url-map.csv – напишите или запланируйте эту страницу. Так вы не тратите время на пустые темы: пишете то, что уже привязано к спросу.

TEYA, офис страниц и установка дизайн-субагента AURA – только после пакета файлов, не вместо него. Углубления по желанию, не обязательны для сегодняшнего результата: семантическое ядро в Cursor, установка AURA, многостраничный сайт с TEYA.

Разборы агентов и MCP – в Telegram t.me/maya_pro и в MAX max.ru/maya_pro. Если понадобится системная практика автоматизаций отдельно от этого маршрута – курс на kv-ai.ru.

Разберем ситуацию новичка: табличка ключей из обычного чата выглядит убедительно, но без url-map вы не знаете, какая страница закроет какой кластер. Ядрышко как раз связывает запросы с картой URL.

Живой пример успеха: в проекте есть .cursor/agents/core.md (или виден /core), Wordstat зелёный, в папке – кластеры и брифы с датой прогона. Так вы получите план на контент, а не список желаний.

Из практики: после пакета сразу не запускайте контент-завод на 50 URL. Возьмите один бриф, напишите одну страницу, замерьте. Иначе хаос масштабирования съест выигрыш от живого Wordstat.

Частые вопросы

Можно ли поставить Ядрышко без Wordstat?

Можно установить файл агента и получить структуру отчёта. Но без зелёного Wordstat MCP частотности обязаны быть помечены неподтверждёнными. Для решения "какие страницы писать" я бы не считал такой прогон закрытым.

Чем это отличается от "попроси Cursor ключи"?

Чат выдаёт список фраз. /core после живого Wordstat кладёт на диск кластеры, карту страниц, брифы и HTML. Проверка – файлы в research/semantic-core-runs, а не красивый абзац в диалоге.

Нужен ли Key Collector в первый прогон?

Нет. Для первого пакета достаточно Cursor, MCP-KV Wordstat и install Ядрышко. Парсер Windows и ручная сборка ядра – другой маршрут, его можно отложить.

Нужно ли сразу ставить TEYA или офис страниц?

Нет. Сначала папка clusters / карта страниц / briefs. Сетку страниц и другие роли имеет смысл после того, как понятно, какие URL писать.

Где лежат файлы после /core?

Обычно в research/semantic-core-runs/ (кластеры, url-map, брифы, HTML). Если папка пустая – дождитесь конца прогона и проверьте URL с регионом, не перезапускайте "наугад".

Что делать, если Wordstat красный в Tools & MCP?

Не вызывайте /core. Сначала почините ключ и роль в MCP-KV, дождитесь зелёного статуса и одной тестовой цифры показов. Иначе пакет уедет с неподтверждёнными частотностями.
