Аня три дня читала «n8n или make», скачала Docker «на всякий случай» и так и не дошла до первого сценария: заявки из формы всё ещё копирует в Telegram руками. Страх «выбрать не то» и поставить сервер вместо теста съедает неделю. Ответ простой: за вечер выберите один путь по таблице, соберите один тестовый workflow и доведите его до зелёного прогона – без обоих аккаунтов и без DevOps.

Если нужен быстрый старт без сервера – чаще Make Free под заявки и автопост. Если много шагов в одном прогоне или позже свой сервер – n8n Cloud trial, не Docker в день-1. На Make 10 модулей ≈ 10 credits за прогон; на n8n Cloud тот же прогон = 1 execution. Линейный сценарий не заменит «долгое мышление»: тогда смотрите агентов, а не второй no-code.

Оба инструмента – конструкторы цепочек: триггер → шаги → действие. Разница не в «кто круче», а в том, куда поставить первый кубик сегодня вечером, пока лиды капают в личку. Ниже – сравнение и чеклист выбора для маркетолога без технического бэкграунда.

Запишите задачу дня-1 одной фразой

Типичная ошибка – хотеть «автоматизировать всё». Так вы никогда не выберете платформу. Сделайте узкую формулировку: «форма или бот → сообщение в Telegram» либо «готовый пост → канал». Это и есть первый результат, который вы сможете запустить без команды разработчиков.

Не делайте второй аккаунт «на всякий». На практике два пустых кабинета дают ноль живых прогонов. Используйте правило: один инструмент → один сценарий → зелёный статус, и только потом думайте о стеке номер два.

  1. Шаг 1: запишите задачу одной строкой без слова «всё».
  2. Шаг 2: отметьте, есть ли у вас админ сервера (да/нет).
  3. Шаг 3: прикиньте число шагов в цепочке (до 5 или больше).
  4. Шаг 4: выберите Make Free, n8n Cloud trial или n8n self-host с админом.
  5. Шаг 5: откройте только выбранный кабинет.
  6. Шаг 6: уберите вкладки с «установкой Docker на всякий случай».

Self-hosted – это когда программа крутится на вашем сервере, а не в чужом облаке. Для новичка без админа self-host n8n в первый вечер – ловушка: в сообществе GitHub есть кейсы потери данных на SQLite после обновлений VPS. Ориентир day-1 – браузерный кабинет.

Например, один прогон из 10 модулей на Make сжигает около 10 credits, а на n8n Cloud тот же прогон списывает одно execution целиком. Добавьте это в прикидку до покупки тарифа.

Выберите путь под заявки или автопост

Если задача – лиды в мессенджер, CRM-строка или пост в канал, сделайте выбор так:

  • Нет админа сервера + короткая цепочка → Make Free.
  • Нет админа, но много шагов в одном прогоне → n8n Cloud trial (14 дней Pro-фич; после trial workspace удаляется, есть окно скачать workflows).
  • Есть админ и нужен свой сервер → n8n Community / Docker по официальной инструкции, не «скачал с форума».

Избегайте формулировки «n8n бесплатный = ставлю Docker сегодня». Бесплатная Community Edition – это self-host; без техники docs сами советуют Cloud. Проверьте: если вы не понимаете слова VPS и SQLite, ваш день-1 – облако.

Для Make подключите Telegram через живой каталог приложения apps.make.com/telegram, а HTTP-запросы – через apps.make.com/http. Не открывайте устаревшие ссылки с главной www – для ботов они часто отдают ошибку доступа.

Соберите один тестовый сценарий до зелёного прогона

В реальном проекте критерий успеха – не «аккаунт создан», а успешный прогон. Workflow здесь – просто цепочка кубиков: откуда пришло → что сделать → куда отправить.

  1. Шаг 1: создайте сценарий в выбранном кабинете (Make scenario или n8n workflow).
  2. Шаг 2: поставьте триггер – webhook формы, Watch Updates бота или ручной запуск.
  3. Шаг 3: добавьте 2–4 действия (запись в таблицу, сообщение в Telegram, публикация черновика).
  4. Шаг 4: токен бота и ключи кладите только в connection/credentials, не в чат и не в публичный пост.
  5. Шаг 5: запустите Run once / Execute workflow один раз вручную.
  6. Шаг 6: проверьте History: зелёный статус, текст дошёл, строка появилась.
  7. Шаг 7: только после этого включайте расписание (у Make Free интервал от 15 минут).

Если выбрали Make и хотите готовые шаблоны цепочек, папка блюпринтов на kv-ai.ru экономит время на сборке модулей – но сначала свой тестовый прогон своими руками.

Чеклист лимитов и граница с агентами

Перед тем как масштабировать, пройдите короткий чеклист расхода и границ.

  1. Прикиньте Make: число модулей × число прогонов ≈ credits (Free даёт до 1 000 в месяц).
  2. Прикиньте n8n Cloud: число прогонов ≈ executions (Starter около 2 500 в месяц на annual).
  3. Core Make от $9 за 10 000 credits; n8n Pro около 50€ annual за 10 000 executions – цифры сверяйте на официальном pricing.
  4. Не делайте оба стека, пока нет одного зелёного прогона.
  5. Если задача = долгий анализ текста, правка сайта или рой субагентов – не форсите Make/n8n: линейный конструктор это не закрывает.
  6. Тогда смотрите агентский контур: экономика агентов в Cursor, вайбкодинг для маркетинга в гайде, связку OpenClaw+Make в установке.

Ориентир канала прост: Make и n8n отлично возят заявки и посты, но для задач с «долгим размышлением» нужен агентский слой, а не второй аккаунт no-code. Репозиторий Horosheff/EXCALIBUR как раз про авто-блог на субагентах – это другой класс задач, не day-1 сравнение.

Критерий успеха до выхода из статьи: выбран один инструмент, собран один живой тестовый сценарий (бот/форма → таблица/Telegram или пост → канал), History зелёный, и вы понимаете правило «когда хватит сценария, а когда звать агента». Результат вечера – работающая доставка, а не спор на форуме.

Частые вопросы

Новичку что лучше – n8n или Make?

Для заявок в Telegram и простого автопоста без сервера чаще Make Free. n8n берите, если нужен Cloud trial под длинный граф или есть админ под self-host. Сделайте выбор по задаче дня-1, не по рейтингу «что круче».

Можно ли начать с бесплатного тарифа?

Да. Make Free даёт до 1 000 credits в месяц. У n8n «бесплатно» без карты – это Community self-host; без админа используйте Cloud trial, затем Starter по pricing. Проверьте лимит до рекламного трафика.

Нужен ли сервер для n8n в первый вечер?

Нет. Не делайте Docker day-1, если нет админа. Официальные docs советуют Cloud тем, кто без техники. Self-host оставьте на потом, когда уже есть зелёный сценарий в облаке.

Чем Make отличается от n8n для автопостинга?

Логика похожа: триггер → текст/медиа → канал. На Make проще готовые приложения и быстрый старт; на n8n удобнее длинные графы и свой сервер. Ориентир: сначала один канал и один ручной прогон.

Когда переходить с Make или n8n на агентов в Cursor?

Когда нужна не доставка «если A, то B», а долгое рассуждение, правка сайта или несколько ролей агента. Избегайте подмены: агент не отменяет простой workflow заявок. Сначала зелёный сценарий, потом агентский контур.

Стоит ли ставить оба инструмента «на всякий»?

Нет. Два пустых аккаунта не дают результата. Выберите один путь, доведите тестовый прогон до History «успех», и только потом сравнивайте второй стек на той же задаче.
