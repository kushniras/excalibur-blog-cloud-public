Вы открыли «код страницы», вставили чужой JSON-LD из генератора – а валидатор Яндекса пишет «микроразметка не обнаружена» или показывает пустые поля. Типичная ошибка: скрипт не сохранился, в типе опечатка, даты не в нужном формате, а вопросы в разметке не совпадают с текстом на экране. Ниже – один вечер, одна уже опубликованная статья и два блока разметки до галочки валидатора, без плагина «на весь сайт».

За один вечер на одной статье вставите два блока JSON-LD (BlogPosting или Article плюс FAQPage с 3–5 реальными вопросами), прогоните через валидатор Яндекса или Schema Markup Validator и увидите распознанные типы без критических ошибок. С 7 мая 2026 Google больше не показывает FAQ-аккордеон в выдаче – ориентир успеха сегодня не сниппет, а галочка валидатора. JSON-LD здесь – машиночитаемая визитка страницы: автор, даты, вопросы и ответы, которые уже видны человеку.

План простой: сначала поля → потом скрипт → потом проверка. Не зоопарк всех типов Schema.org и не ожидание «магии AI» из-за разметки.

Чем микроразметка отличается от HTML и llms.txt

Красивый HTML показывает текст людям. Микроразметка – это скрытый для глаза, но читаемый роботами слой фактов о странице. JSON-LD (JavaScript Object Notation for Linked Data) – формат, который Google рекомендует как самый простой: один скрипт в коде страницы, без правок каждого абзаца.

Файл llms.txt – другая история: подсказка AI-краулерам, какие страницы читать. Он не заменяет Schema.org и не даёт типов BlogPosting или FAQPage в валидаторе. Open Graph отвечает за превью в соцсетях. Не делайте из трёх инструментов один «универсальный код».

На практике микроразметка – гигиена SEO и rich results, а не кнопка «попасть в Алису». Google в гайде по AI-оптимизации прямо пишет: отдельная schema «для generative AI» не нужна. Для нейроответов есть соседний чеклист продвижения в нейросетях.

Соберите поля статьи для BlogPosting

Выберите одну уже опубликованную статью. Не трогайте весь шаблон сайта в день один. Соберите короткую карточку полей – это и есть заготовка под тип BlogPosting или Article.

  1. Шаг 1. Скопируйте заголовок страницы (H1) – это поле headline.
  2. Шаг 2. Возьмите полный URL статьи – это поле url / mainEntityOfPage.
  3. Шаг 3. Добавьте ссылку на обложку в поле image (полный https-адрес картинки).
  4. Шаг 4. Пропишите datePublished и dateModified в формате ISO 8601, например 2026-07-17.
  5. Шаг 5. Укажите автора как Person с name и url (профиль или «О нас»).
  6. Шаг 6. Проверьте, что в карточке нет пустых строк – валидатор Яндекса часто ругается именно на них.

Ориентир по полям Google: headline, image, даты и author. Если дата написана как «17.07.2026» без ISO, Яндекс может дать предупреждение о некорректном значении.

Мини-шаблон BlogPosting (подставьте свои значения):
«@context»: «https://schema.org»
«@type»: «BlogPosting»
«headline»: «Заголовок статьи»
«image»: «https://example.com/cover.jpg»
«datePublished»: «2026-07-17»
«dateModified»: «2026-07-17»
«author»: { «@type»: «Person», «name»: «Имя», «url»: «https://…» }
«url»: «https://example.com/statya/»

Как оформить FAQPage один к одному с текстом

FAQPage – это не «секретный» блок только для роботов. Вопросы и ответы в разметке должны совпадать с тем, что видит человек на странице. Если в JSON пять вопросов, а на экране три – уберите лишнее из скрипта или допишите видимый блок.

  1. Выберите 3–5 вопросов, которые уже есть в тексте статьи (или добавьте видимый блок FAQ перед публикацией разметки).
  2. Для каждого вопроса используйте пару Question → name и acceptedAnswer → text.
  3. Скопируйте формулировки дословно: без «красивого» пересказа только для JSON.
  4. Не делайте фейковые отзывы и рейтинги «для SEO» – это отдельная ловушка.
  5. Сверьте список глазами: человек видит те же Q&A, что и валидатор.
  6. Оставьте FAQPage даже после отмены FAQ rich results в Google: тип Schema.org валиден, а критерий успеха у вас – валидатор, не аккордеон в выдаче.
  7. Готовые примеры лежат в открытых репозиториях вроде TryGeoSuite/schema-templates и Structured-Data-JSON-LD – копируйте структуру, не чужие URL и даты.

С 7 мая 2026 Google больше не показывает FAQ rich results ни для каких сайтов. Отчёт и поддержка в Rich Results Test для FAQ уходят летом 2026. В Google имеет смысл проверять Article/BlogPosting, а не ждать выпадающий FAQ-сниппет.

Вставьте JSON-LD на одну страницу без плагина

Страх «сломать сайт кодом» лечится узким периметром. Правите копию или черновик одной записи. Не ставьте Rank Math «на весь сайт» в первый вечер.

  1. Сделайте резервную копию текста статьи или дубликат черновика.
  2. Оберните JSON в тег script с type=»application/ld+json» (как в документации Google по structured data).
  3. Добавьте один или два таких блока перед закрывающим body – либо через Custom HTML в редакторе, либо правкой одной записи.
  4. Можно объединить BlogPosting и FAQPage через @graph в одном скрипте – тогда меньше шансов потерять второй блок.
  5. Сохраните и откройте страницу: вёрстка должна выглядеть как раньше.
  6. В браузере откройте «просмотр кода» и найдите свой script – если его нет в исходнике, валидатор тоже ничего не увидит.

Workflow вечера: поля карточки → script JSON-LD → сохранение → просмотр кода → валидатор.

Избегайте генераторов «вставь и забудь» без проверки исходника. Чужой JSON часто содержит чужой @type с опечаткой или пустые поля – отсюда «микроразметка не обнаружена».

Проверьте разметку в валидаторе Яндекса

Откройте валидатор микроразметки Яндекса (Вебмастер → Валидатор) или универсальный Schema Markup Validator. Проверьте URL страницы или вставьте HTML-фрагмент со скриптом.

Что должно получиться: распознаны типы BlogPosting (или Article) и FAQPage, нет ошибки «микроразметка не обнаружена». Для Google дополнительно можно прогнать Article через Rich Results Test – но FAQ-аккордеон там уже не цель.

Если валидатор молчит, пройдите короткий разбор:

  1. Проверьте, что в исходнике есть script и корректные кавычки в JSON.
  2. Проверьте @context = https://schema.org и точное написание @type.
  3. Проверьте даты в ISO 8601.
  4. Проверьте, что FAQ в разметке совпадает с видимым текстом.
  5. Исправьте пустые поля и снова отправьте URL.

После успешной проверки сниппет в Яндексе может появиться не сразу – в справке ориентир порядка двух недель на переобход. Это не отменяет вечерний результат: типы уже видны в валидаторе.

Частые вопросы

Нужен ли плагин Schema, чтобы добавить микроразметку?

Нет для первого вечера. Сделайте один или два script JSON-LD на одной статье, проверьте валидатором. Плагин имеет смысл позже, если размечаете десятки шаблонов сразу.

Почему валидатор пишет «микроразметка не обнаружена»?

Чаще всего скрипт не попал в сохранённый HTML, сломан JSON или неверный @type. Откройте исходник страницы, найдите script, исправьте поля и снова проверьте URL.

Стоит ли удалять FAQPage после отмены FAQ в Google?

Не обязательно. Тип остаётся в Schema.org, вопросы помогают понять структуру страницы. Просто не ждите аккордеон в выдаче Google – ориентир успеха сменился на валидатор.

Чем микроразметка отличается от llms.txt?

Микроразметка описывает факты страницы для поисковиков (автор, даты, Q&A). llms.txt – отдельный файл-подсказка для AI-краулеров. Используйте оба инструмента по назначению, не смешивайте в один блок.

Какой формат даты принимать валидаторы?

Для Яндекса ориентир – ISO 8601 (например 2026-07-17 или с временем и зоной). Избегайте «человеческих» дат только в тексте разметки без ISO.

Когда ждать сниппет в Яндексе после галочки?

Валидатор может показать типы сразу. Структурированный сниппет в выдаче – после переобхода, в справке Яндекса ориентир около двух недель. Ускорить обход помогает IndexNow.
