Вы копируете в чат «напиши продающее описание» без размеров и состава – нейросеть придумывает «гарантию 5 лет» и «шок-цену». Боитесь залить это в кабинет: жалобы, возвраты, просадка в поиске. Ниже другой путь: файл фактов рядом с черновиком в Cursor, ИИ пишет только по вашим данным, чеклист бан-слов (запрещённых формулировок площадки) – и один SKU (позиция товара) готов к вставке. Без ТОП-генераторов и без обещания «+300% продаж».

Механизм простой: product-facts.md → бриф из 5–15 ключей → помощник в Cursor собирает cards/<sku>-wb.md (или -ozon.md) → сверка цифр и запрещённых формулировок → кабинет продавца. Результат вечера – текст с блоками «для кого / преимущества / характеристики / применение» и пометкой «факты проверены», который сможете вставить в карточку. Не рейтинг SaaS и не массовая автозаливка в кабинет без вычитки.

В выдаче по запросу «описание товара нейросеть» почти сплошь онлайн-генераторы и «ТОП-25 ИИ». Люди чаще ищут само «описание товара» – результат для карточки. Ниже – путь с файлом на диске, который повторите на следующий артикул.

Сравните три пути: чат, SaaS и файл в Cursor

Одно слово «нейросеть» тянет три разные машины. Если взять не ту – снова вода с выдуманными свойствами.

Путь Что получаете Риск для карточки
Чат «напиши описание» Быстрый абзац без связи с вашим составом Выдуманные гарантии, материал, «шок-цена»
Онлайн-генератор в чужом UI Текст за секунды, но живёт в сервисе Завтра не повторите процесс; фактчек всё равно на вас
Cursor + product-facts.md Черновик в cards/ на диске, повторный рецепт Низкий, если сверяете цифры и бан-слова

Контраст короткий: генератор продаёт скорость, файл фактов – контроль. На практике селлер платит дважды: сервису и возвратами за фантазии модели. Не делайте MVP из «ТОП-25»: выберите один SKU и редактор с папкой проекта.

Прогресс: выбран путь «файл на диске», не чат и не чужой UI.

Соберите product-facts.md без рекламных фантазий

Пока нет таблицы фактов, любая модель дорисует свойства «для красоты». Сделайте папку marketplace-cards/ в Cursor и положите рядом пустой cards/<sku>-wb.md (для Ozon – суффикс -ozon).

  1. Шаг 1. Создайте product-facts.md в корне папки проекта.
  2. Шаг 2. Запишите название, категорию, материал или состав – только то, что есть на этикетке или у поставщика.
  3. Шаг 3. Добавьте размеры, вес, комплектацию и «для кого» одной фразой.
  4. Шаг 4. Перечислите 3–5 преимуществ без суперлативов вроде «лучший на рынке».
  5. Шаг 5. Укажите площадку: WB или Ozon – лимиты длины разные.
  6. Шаг 6. В конце файла напишите жёсткое правило: «не добавляй свойства от себя».

Типичная ошибка – смешать факты и рекламу в одном списке. Уберите из фактов всё, что не подтвердите документом.

Прогресс: product-facts.md заполнен, фантазий нет.

Как добавить ключи в бриф, чтобы карточку находили

Без поисковых фраз описание красиво, но молчит в выдаче маркетплейса. Не нужно собирать ядро на сто ключей в первый вечер – хватит короткого брифа.

  1. Шаг 1. Выпишите 5–15 фраз, как покупатель ищет товар (из кабинета, подсказок поиска или Wordstat).
  2. Шаг 2. Отметьте 1–2 главных запроса и 3–5 вспомогательных.
  3. Шаг 3. Для WB помните: одно ключевое слово в описании – не чаще трёх раз.
  4. Шаг 4. Если ключи «на глаз» – позже подключите Ядрышко и настройку Wordstat через MCP (протокол связи Cursor с внешними сервисами); первый результат без этого возможен.
  5. Шаг 5. Вложите список в бриф рядом с product-facts.md, не в чат отдельным сообщением «где-то там».

Например, для термокружки фразы «термокружка 500 мл», «кружка с крышкой в офис» важнее общих «качественный товар». Глубже про семантику – соседний гайд семантическое ядро в Cursor.

Прогресс: бриф из 5–15 фраз лежит рядом с фактами.

Запустите черновик cards/<sku>-wb.md только по фактам

Cursor – это редактор с ИИ-помощником рядом с файлами проекта, а не чат в браузере. Agent (режим, где ИИ правит файлы по задаче) читает product-facts.md и пишет черновик в cards/.

Composer (модель Cursor для длинных задач) удобен, когда черновик большой и нужны правки по кругу. Skill и Rules – после первого удачного файла, не вместо него.

  1. Шаг 1. Откройте пустой cards/<sku>-wb.md (или -ozon.md).
  2. Шаг 2. Попросите Agent: структура «для кого → преимущества → характеристики → применение»; длина примерно 1500–2500 символов.
  3. Шаг 3. Явно скажите: только факты из product-facts.md; русский язык; без бан-слов из чеклиста ниже.
  4. Шаг 4. Используйте ориентир SellerMoon ~1500–1800 символов для SEO-описания, если не уверены в «максимуме».
  5. Шаг 5. На WB потолок описания около 5000 символов, на Ozon около 6000; рабочий объём чаще короче.
  6. Шаг 6. Сохраните файл на диске – не копируйте черновик только в буфер обмена.
  7. Шаг 7. Если кнопки путают – карта новичка в Cursor Junior; углубление – гайд по Skills для маркетинга и гайд по Composer.

Пример запроса Agent:

Прочитай product-facts.md. Напиши описание для Wildberries только по этим фактам. Структура: для кого → преимущества → характеристики → применение. Длина 1600–2200 символов. Русский язык. Не добавляй свойства от себя. Без бан-слов и ложных гарантий. Ключи из брифа – естественно, на WB одно слово не чаще трёх раз. Сохрани в cards/<sku>-wb.md; в конце пока строка «факты проверены: нет».

Повторяемый рецепт оформите как Skill (файл SKILL.md) или короткое правило в Rules: «не выдумывай свойства». Тогда следующие артикулы идут быстрее разового чата.

Прогресс: на диске есть черновик cards/<sku>-*.md.

Чеклист: проверьте факты, бан-слова и 168-ФЗ

Сгенерированный текст почти всегда нуждается в фактчеке – это норма, не провал. До кабинета пройдите короткий чеклист.

  1. Сверьте каждую цифру и свойство с product-facts.md – лишнее уберите.
  2. Проверьте повтор главного ключа на WB: не больше трёх раз.
  3. Избегайте формулировок вроде «шок-цена», «лучший», гарантий, которых нет в фактах.
  4. С 01.03.2026 по 168-ФЗ потребительская информация на маркетплейсах – на русском; иностранные слова без перевода – риск.
  5. Длина: разумный диапазон 1500–3000 (WB) или 2000–3500 (Ozon), не «простыня до лимита».
  6. В конце файла поставьте пометку «факты проверены» и дату.
  7. Не делайте массовую автозаливку через Seller API (программный доступ к кабинету продавца) в первый вечер – сначала текст глазами.

В реальном проекте часто ломается доверие: модель дописала «хлопок 100%», а на бирке смесовая ткань. Без жёстких фактов нейросеть выдумывает свойства – отсюда возвраты и жалобы. MCP к Wildberries – next-step, когда текст стабилен.

Прогресс: цифры сходятся, бан-слова сняты, пометка «факты проверены» стоит.

Вставьте текст в кабинет и закрепите порядок на следующие SKU

Workflow (порядок шагов) – это ваша цепочка: факты → бриф → Agent → чеклист → кабинет. Скопируйте готовый текст в карточку продавца. Не обещайте себе рост ранга от одного абзаца: ставка вечера – понятный текст, который покупатель дочитывает и который не стыдно публиковать.

Что дальше после первого файла:

  • Тот же Skill/Rule на следующий артикул – быстрее, чем писать с нуля.
  • Визуал карточки: генерация картинок в Cursor и обложка нейросетью.
  • Сосед по ИИ-тексту (статья, не карточка МП): написать статью нейросетью.
  • Вход в вайбкодинг маркетолога: вайбкодинг в Cursor; MCP-база: подключение MCP.

Разборы и шаблоны – в Telegram «Ковчег» и в канале MAX. Если нужен системный курс по автоматизации – обучение Make (не больше одного упоминания курса).

Вечером у вас не «вода из чата», а paste-ready файл: блоки на месте, факты сверены – сможете вставить текст в кабинет. Результат проверяется глазами за пять минут, не обещанием продаж.

Прогресс: текст в кабинете или готов к вставке; процесс повторяем на следующий SKU.

Частые вопросы

Подойдёт ли путь с Cursor селлеру без опыта разработки?

Да. Работаете с текстовыми файлами и Agent, не с кодом. Первый результат – один .md на диске. Карта кнопок – Cursor Junior на GitHub.

Чем этот способ лучше онлайн-генератора за 30 секунд?

Генератор даёт текст в чужом окне. Здесь черновик лежит у вас, правила повторяются, а факты вы задаёте до генерации. Скорость похожа, контроль выше.

Сколько символов писать для WB и для Ozon?

Потолки площадок выше, но на практике берите 1500–3000 для WB и 2000–3500 для Ozon. Ориентир SEO-описания около 1500–1800, если не знаете, с чего начать.

Что делать, если модель снова выдумала характеристику?

Проверьте product-facts.md: правило «не добавляй от себя» должно быть в файле и в запросе. Уберите выдумку, исправьте черновик, только потом кабинет. Без жёстких фактов галлюцинации вернутся.

Нужен ли Skill с первого дня?

Нет. Сначала один удачный cards/<sku>-wb.md вручную. Skill имеет смысл, когда процесс уже понятен и вы хотите ускорить следующие артикулы.

Стоит ли сразу заливать описания в кабинет без ручной вычитки?

Нет. Сначала текст и чеклист глазами. Автозаливка через API или community MCP к Seller API – next-step после стабильного шаблона, не замена фактчека.

Подойдёт ли тот же файл под WB и Ozon без правок?

База фактов общая, но лимиты и плотность ключей разные. Держите отдельные cards/<sku>-wb.md и -ozon.md или явно просите Agent адаптировать длину под площадку.
