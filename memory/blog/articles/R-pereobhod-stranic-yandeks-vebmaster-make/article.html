Заголовок на сайте уже новый, а в Яндексе всё ещё старый – знакомо? Боль в том, что после каждой правки вы снова открываете Вебмастер и копируете URL руками, боясь пропустить страницу и "сжечь" квоту. Ответ проще страха: таблица URL в Google Sheets и один сценарий Make с HTTP POST в очередь переобхода. За вечер вы получите task_id, остаток квоты и статус "В очереди" – без кода и без копипаста в кабинете.

Когда переобход не запускать

Если страница ещё черновик или закрыта от индекса – переобход не поможет. Если лимит Вебмастера на исходе – не гоняйте пачку URL без приоритета. Типичная ошибка: дергать одну и ту же ссылку каждый час. На практике список важных URL → Make → статус в Sheets.

Переобход страниц – это не "магия индексации", а просьба роботу Яндекса раньше заглянуть на ваши URL. IndexNow только стучит об изменении; Sitemap и обход по Метрике работают фоном. За один вечер: OAuth Вебмастера → user-id и host-id → Sheets со списком URL → Make HTTP POST в recrawl/queue → task_id и quota_remainder в таблице. Ориентир успеха: HTTP 202 в History и URL со статусом "В очереди" в кабинете.

Выберите инструмент: переобход, IndexNow или ожидание робота

Какую боль закрываем: путаницу "что жать после публикации". Переобход страниц яндекса – это приоритетная очередь обхода в Вебмастере. IndexNow – короткое уведомление поисковикам об изменении. Sitemap и обход по Метрике – постоянный фон, не "кнопка после правки".

Задача Инструмент Что получите
Срочно попросить робота прийти на URL Переобход (UI или API) URL в очереди, task_id, квота
Быстро стукнуть об изменении IndexNow через Make Пинг без гарантии индексации

Вердикт для новичка: после срочной правки заголовка, редиректа или фикса ошибки используйте переобход. Для массовых мелких правок часто хватает IndexNow. Не делайте оба действия "на всякий случай" без понимания квоты.

Перед массовой отправкой имеет смысл пройтись по диагностике: закрыта ли страница от индексации, отдают ли URL код 200. В этом помогает SEO+GEO skill для Cursor и соседний гайд по robots.txt и sitemap.

Получите OAuth Вебмастера: токен, user-id и host-id

Боль: "API только для программистов". Сделайте приложение на oauth.yandex.ru как "логин для робота", а не как код на сервере.

  1. Шаг 1. Создайте приложение типа "Веб-сервисы" на oauth.yandex.ru.
  2. Шаг 2. Укажите Redirect URI https://oauth.yandex.ru/verification_code.
  3. Шаг 3. Выдайте доступы webmaster:hostinfo и webmaster:verify.
  4. Шаг 4. Скопируйте OAuth-токен (действует около 6 месяцев) только в Connection Make.
  5. Шаг 5. Через HTTP GET получите user-id: запрос к /v4/user.
  6. Шаг 6. Через GET /v4/user/{user-id}/hosts найдите host-id подтверждённого сайта.
  7. Шаг 7. Проверьте квоту GET …/recrawl/quota – запишите daily_quota и quota_remainder в Sheets.

Типичная ошибка: кинуть токен в Telegram "на память". Уберите его из чатов и из публичных документов. Без токена API отвечает 401 – это не "сломали сайт", а просто нет авторизации. Как повесить OAuth/Bearer на HTTP-модуль, смотрите в справке Make по OAuth 2.0.

Соберите workflow Make: Sheets → Iterator → HTTP POST

Боль: час копипаста URL после каждой публикации. Workflow на пальцах: таблица со списком ссылок → кубик, который берёт строки по одной → HTTP-запрос "поставь URL в очередь" → запись ответа обратно в строку.

  1. Откройте приложение HTTP в Make и создайте сценарий.
  2. Добавьте Google Sheets: колонка URL (и пустые колонки task_id, quota_remainder, status).
  3. Поставьте Iterator по строкам таблицы.
  4. Сделайте HTTP Make a request: POST на https://api.webmaster.yandex.net/v4/user/{user-id}/hosts/{host-id}/recrawl/queue
  5. В теле JSON укажите {"url":"{{url}}"}. В заголовке – Authorization с OAuth-токеном.
  6. Запишите в Sheets поля task_id и quota_remainder из ответа 202.

Схема дня 1:
Sheets (URL) → Iterator → HTTP POST recrawl/queue → Update row (task_id + quota_remainder) → сверка в Вебмастере

Например, для контент-завода достаточно 1–3 URL новой статьи, а не всей карты сайта. Если сценарии Make ещё в новинку, разберите базу в гайде автоматизация Make с AI Agents или возьмите готовый каркас из папки блюпринтов.

Проверьте первый прогон: History, task_id и очередь

Боль: "запустил и не понимаю, сработало ли". Критерий простой и видимый.

Сделайте Run once на одном тестовом URL, который уже отдаёт 200 и не закрыт от индексации. В History Make должен быть HTTP 202 с task_id и числом quota_remainder. Затем откройте Вебмастер: Индексирование → Переобход страниц – тестовый URL со статусом "В очереди" или позже "Заявка обработана".

Проверьте три вещи до FAQ-уровня спокойствия:

  • в Sheets записаны task_id и остаток квоты;
  • в кабинете URL виден в очереди переобхода;
  • страница открывается без noindex и без блокировки в robots.

Индексирование после отправки может занять от 3 до 7 дней – ориентир из справки Яндекса, не "мгновенный ТОП". Если нужно усилить саму SEO-страницу до переобхода, смотрите как собрать SEO-страницу в Cursor. Для аудита перед очередью пригодится SEO+GEO skill на GitHub.

Чеклист квоты и ошибок: 409, 429 и что не слать

Боль: сжечь суточную квоту или слать один URL дважды. Используйте этот чеклист перед каждым массовым прогоном.

  1. Сначала GET recrawl/quota – не гадайте "сколько можно сегодня".
  2. Шлите только HTML/контент-URL: статьи, лендинги, карточки.
  3. Не делайте переобход для robots.txt, favicon.ico и Sitemap – у них другие разделы Вебмастера.
  4. Добавьте Sleep между запросами, чтобы не долбить API пачкой.
  5. При 409 URL_ALREADY_ADDED – URL уже в очереди: не ретрайте сегодня.
  6. При 429 QUOTA_EXCEEDED – остановите сценарий и дождитесь сброса квоты.
  7. Раз в ~6 месяцев обновите OAuth-токен, иначе History уйдёт в 401.
  8. Избегайте отправки URL, которые ещё отдают 404 или закрыты meta robots.

В реальном проекте сообщество уже собирает обёртки и MCP вокруг тех же endpoint queue/quota – сигнал, что боль автоматизации живая. Вам на день 1 достаточно Make HTTP, без Python-клиента.

Когда хватит IndexNow, а когда нужен именно переобход: срочная правка title/редирект/фикс после ошибки → переобход; регулярные мелкие апдейты большого объёма → чаще IndexNow (см. соседний гайд). Для конвейера публикаций держите в уме контент-завод на нейросетях: переобход – финальный кубик после выкладки, не замена качеству текста.

Частые вопросы

Чем переобход страниц отличается от IndexNow?

IndexNow уведомляет поисковики об изменении URL. Переобход ставит адрес в приоритетную очередь обхода Яндекс Вебмастера. Можно совмещать, но сначала выберите задачу: "стукнуть" или "попросить робота прийти раньше".

Сколько URL в сутки можно отправить на переобход?

Смотрите свою квоту через GET recrawl/quota (daily_quota и quota_remainder). В кабинете лимит тоже суточный и обновляется ежедневно. Не копируйте чужие цифры "20 или 10000" без проверки своего host-id.

Нужен ли OAuth или хватит кабинета Вебмастера?

Для пары URL вручную хватит раздела "Переобход страниц". Для Make и автопубликации нужен OAuth-токен и API. Токен кладите только в Connection, не в чат.

Можно ли слать URL сразу после публикации в Make?

Да, сразу после того как страница отдаёт 200 и не закрыта от индексации. Иначе в кабинете увидите статус "Ошибка", а квота уже потрачена.

Что делать при QUOTA_EXCEEDED или URL_ALREADY_ADDED?

При 429 остановите сценарий и дождитесь сброса квоты. При 409 URL уже в очереди – не отправляйте повторно сегодня. Запишите код ошибки в колонку status, чтобы не гадать по History.

Почему "Заявка обработана" не значит, что страница в индексе?

Это значит, что робот посетил URL. Данные могут обновляться до двух недель, а индексация всё равно зависит от robots, meta и качества страницы. Переобход ускоряет визит, но не покупает место в выдаче.
