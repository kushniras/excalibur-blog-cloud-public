Лена ведёт лендинг на Тильде и раз в неделю пишет кейс. Генерит текст в ChatGPT, потом сорок минут копирует: заголовок сюда, описание туда, SEO забыла, обложку отдельно, alt пустой. После третьей статьи бросает блог: «Потоки» кажутся для программистов. Ответ за вечер: включить модуль Потоки, поставить Tilda AI Agent Feeds и кнопкой «Заполнить всё» получить SEO-черновик – без кода и без копипаста по десяти полям.

Потоки на Тильде – лента постов (до 5000 в одном потоке), а не «ещё одна страница». Workflow новичка: модуль в Настройках → поток «Блог» → расширение из GitHub → ключ нейросети → «Заполнить всё» → вычитка → Опубликовать. Сюрприз: у Publishing API Тильды нет create/publish поста в Потоки (только чтение и экспорт). Массовый штатный вход – CSV, а «нейросеть → поля в редакторе» закрывает браузерный агент, не REST как у WordPress. Спрос: «потоки тильда» – 574 показов/мес, «нейросеть для написания статьи» – 559 (Яндекс Вордстат, Россия, 14.07.2026).

Выберите Потоки вместо «страница = пост»

Боль «не понимаю Потоки, боюсь сломать сайт» закрывается выбором. На практике блог на Тильде делают двумя путями: отдельная страница под каждый пост (редко, когда нужен уникальный дизайн) или Потоки – лента однотипных материалов с шаблоном карточки. Посты не съедают лимит страниц проекта; у каждого потока свой sitemap, так что поисковик видит ленту отдельно от лендинга.

Например, лендинг услуг оставляете как есть, а кейсы и новости кладёте в поток «Блог». Официальная справка Тильды так и делит сценарии. Не делайте блог из десяти страниц-клонов: править SEO и даты станет муторнее, чем в редакторе потока.

Критерий Список страниц Потоки ChatGPT + копипаст
Скорость Каждая страница отдельно Мгновенно в плитке Быстрый текст, медленные поля
SEO-поля Вручную на странице В карточке поста Часто забываются
Лимит Съедает страницы До 5000 постов вне лимита Не про CMS
Когда брать 1–2 уникальных лонгрида Регулярный блог на тильде Черновик идей, не финал

Вердикт: для кейсов и SEO-статей используйте Потоки. ChatGPT – для идеи; поля редактора отдайте агенту или честной вычитке.

Как включить модуль и создать поток «Блог»

Безопасный первый шаг – включить модуль, не трогая лендинг. Сделайте по схеме help-ru.tilda.cc:

  1. Шаг 1. Настройки сайта → Подключаемые модули → Потоки → Подключить.
  2. Шаг 2. Создайте поток с именем «Блог» или «Кейсы».
  3. Шаг 3. Добавьте пустой пост с названием-заглушкой.
  4. Шаг 4. Проверьте, что в панели есть Потоки и пост открывается в редакторе.
  5. Шаг 5. Убедитесь: лендинг на главной не изменился.
  6. Шаг 6. При желании добавьте блок ленты на страницу «Блог».

Типичная ошибка – сразу лить CSV. CSV умеет до 50 Мб и 5000 строк, но картинки с внешних URL не подтягиваются. Избегайте массового импорта в первый вечер – сначала один живой пост.

Установка Agent Feeds: GitHub → режим разработчика

Боль «страшно ставить с GitHub» снимается ритуалом распакованного расширения Chrome. Репозиторий Horosheff/Tilda-AI-Agent-Feeds – открытый код (создан в феврале 2026, обновлён 10.07.2026). Это не «хак сайта», а панель поверх редактора Потоков. Manifest V3 – формат современного расширения: браузер знает, какие скрипты можно вставлять на страницу. DOM – разметка полей на экране: агент заполняет то, что вы видите в форме, а не дергает скрытый серверный API.

  1. Шаг 1. Скачайте ZIP с GitHub и распакуйте папку.
  2. Шаг 2. Откройте chrome://extensions (или аналог в Яндекс.Браузере).
  3. Шаг 3. Включите «Режим разработчика» – тумблер сверху, не консоль.
  4. Шаг 4. «Загрузить распакованное» → папка с manifest.json.
  5. Шаг 5. В popup вставьте ключ kie.ai и/или Google AI Studio, сохраните имя автора.
  6. Шаг 6. В редакторе поста проверьте панель «Tilda IA Agent».
  7. Шаг 7. Если панели нет – обновите вкладку; нужен редактор потока, не Zero Block.

Ориентир установки – @maya_pro/1275; анонс (Wordstat, обложки, Tone of Voice) – #1274. Не делайте коллекцию из десяти расширений: достаточно одного Agent Feeds.

Почему нельзя «просто через API»

Многие слышали «через API Тильды нельзя» – и останавливаются. Честно: Publishing API даёт getproject/getpage/export и webhook наружу, а create/publish поста в Потоки официально нет. Community-обходы и платный RPA на Playwright – путь команд, не маркетолога за один вечер.

В реальном проекте новичка выигрывает расширение: оно пишет в поля редактора у вас на глазах. Local RAG в README агента – не «магическая база», а локальные заметки тона голоса, чтобы текст звучал как ваш бренд, а не как случайный ChatGPT. Используйте агент как помощника редактора, а не как автопилот без вычитки.

Схема workflow:
Тема → пресет тона → «Заполнить всё» → Title/Description/тело/SEO/обложка → правка фактов → Опубликовать

Соберите черновик кнопкой «Заполнить всё»

Боль «копипаст по десяти полям» закрывается одной кнопкой. На практике: открываете пустой пост → в панели агента указываете тему и факты (что продаёте, для кого, какой кейс) → выбираете пресет тона → жмёте «Заполнить всё». Агент расставляет заголовок, краткое описание, SEO Title/Description, ключевики, slug, теги, автора, alt и обложку.

Сделайте один черновик, не десять. Проверьте глазами: цифры выручки и названия продуктов не выдуманы, ссылки ведут куда нужно, обложка читаема. Уберите из текста воду и пустые обещания. Добавьте в тело один конкретный пример из вашего бизнеса – так статья перестаёт быть «нейросетевым шаблоном».

Слабые обложки усиливайте отдельно: генерация картинок через MCP. Перед генерацией текста полезно семантическое ядро и Wordstat.

Чеклист перед публикацией: факты, SEO, alt

Боль «статьи не ищутся» решается коротким ритуалом. До «Опубликовать» пройдите чеклист:

  • Название и описание совпадают с телом.
  • SEO Title и Description заполнены без дубля «главная».
  • Обложка на месте, alt не пустой.
  • Нет выдуманных цифр и чужих кейсов.
  • Пост в нужном разделе (или отложен датой).
  • После публикации карточка видна в плитке на сайте.

Критерий успеха на сегодня: в Потоках открыт пост в статусе «опубликован» или готовый черновик с заполненными названием, описанием, телом, SEO Title/Description и обложкой; панель «Tilda IA Agent» видна в редакторе; вы понимаете, что дальше правите один-два факта и жмёте «Опубликовать», а не собираете статью с нуля вручную. Избегайте публикации без вычитки: нейросеть ускоряет поля, ответственность за факты остаётся вашей.

Для соцсетей параллельно смотрите нейросеть для постов и Make. Глубже без кода – курс Make.com и вайбкодинг и канал @maya_pro.

Частые вопросы

Как добавить поток в Тильде новичку?

Сделайте: Настройки → Подключаемые модули → Потоки → Подключить → создать поток → добавить пост. Проверьте, что раздел Потоки виден в панели.

Нужна ли Тильда, если уже есть WordPress?

Если сайт на Тильде – ведите блог в Потоках, не переносите всё ради API. WP удобнее для write-API; Тильда – для скорости лендинга. Не делайте двойной блог без причины.

Чем Tilda AI Agent отличается от автопостинга в Make?

Agent Feeds заполняет поля Потоков в браузере. Make чаще доставляет пост в соцсети и таблицы. Используйте агент для Тильды, Make – для доставки.

Можно ли генерировать обложку вместе со статьёй?

Да: обложка входит в «Заполнить всё» через kie.ai. После генерации проверьте кириллицу и смысл кадра. При слабом результате замените обложку вручную.

Сколько черновиков безопасно в день?

Ориентир – 1–3 черновика с вычиткой, не конвейер «20 в прод». Избегайте пачки без проверки SEO Title/Description.

Что делать, если панели агента нет?

Проверьте: расширение включено, выбран manifest.json, открыт пост Потоков, вкладка обновлена. Уберите конфликтующие расширения на tilda.cc. Иначе – переустановите папку по README GitHub.
