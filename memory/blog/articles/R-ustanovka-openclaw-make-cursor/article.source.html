OpenClaw – это локальный gateway (шлюз) для AI-агента: он живёт у вас на компьютере и отвечает в Control UI, а не «ещё один чат в браузере». Сравните роли: OpenClaw, Make и Cursor Cloud Agents

Боль «зачем мне ещё один инструмент, если есть Make и Cursor» закрывается не лозунгами, а ролями. На практике Make – это доставка и интеграции (пост, Sheets, Telegram). Cursor – длинная работа в IDE над сайтом и промптами. OpenClaw – 24/7 gateway рядом с мессенджерами и skills. Если нужен только сценарий «форма → уведомление», сначала смотрите Make AI Agents и MCP.

Критерий OpenClaw Make Cursor Cloud Agents
Где живёт Локально (self-hosted gateway) Облако сценариев Облако Cursor / IDE
Сильная сторона Агент + skills + чат Триггеры и модули Долгие задачи в коде
Риск новичка API overnight, чужие skills Сложный сценарий без цели Лишние агенты без брифа
Когда брать Нужен воркер «всегда на связи» Нужна доставка и CRM Нужна работа в проекте Cursor

Вердикт: не делайте стек «всё сразу». Используйте OpenClaw, если нужен агент у себя; Make – если нужна доставка; Cursor – если правите сайт и промпты. Сравнение с облачными агентами – в Cursor Cloud Agents и AI-агентах маркетинга на субагентах.

Установите OpenClaw официальным скриптом и проверьте gateway

Боль «это только для админов / сломаю систему» снимается одним официальным installer – без Docker и VPS в первый вечер. OpenClaw AI ставит себе Node нужной ветки (ориентир docs: 22/24/25). Gateway – это «диспетчер» агента; Control UI обычно слушает порт 18789 на localhost (только ваш ПК).

  1. Шаг 1. Откройте официальный гайд docs.openclaw.ai/install и выберите ОС.
  2. Шаг 2. Mac/Linux/WSL: curl -fsSL https://openclaw.ai/install.sh | bash. Windows PowerShell: iwr -useb https://openclaw.ai/install.ps1 | iex.
  3. Шаг 3. Проверьте openclaw —version – команда должна ответить без ошибки.
  4. Шаг 4. Сделайте onboard: openclaw onboard —install-daemon и добавьте API-ключ модели.
  5. Шаг 5. Запустите openclaw gateway status и openclaw dashboard – откройте Control UI.
  6. Шаг 6. Отправьте тестовое «привет» и дождитесь ответа агента.
  7. Шаг 7. Убедитесь, что версия не ниже патча CVE-2026-25253 (в гайдах hardening – ≥2026.1.29) и gateway не торчит в интернет.

Типичная ошибка – сразу «пробросить порт 18789 наружу». Избегайте публичного gateway: pairing и allowFrom – только для тех, кому доверяете. В реальном проекте достаточно localhost и одного тестового чата. Если Cursor ещё не стоит – сначала вайбкодинг маркетинга в Cursor, а OpenClaw подключайте вторым слоем.

Добавьте один безопасный skill под маркетинг

Skill – это папка с инструкцией SKILL.md: агент получает «специальность» (SEO, Метрика), а не бесконечный свободный доступ. Боль «поставлю левый пакет и утекут ключи» решается allowlist и автором, которого можно проверить на GitHub.

  1. Шаг 1. Выберите один skill: SEO+GEO (github.com/Horosheff/google-yandex-seo-skill или зеркало на ClawHub) либо Метрику (yandex-metrika-assistant).
  2. Шаг 2. Установите через openclaw skills install (slug или git:owner/repo) по доке ClawHub.
  3. Шаг 3. Прогоните skills verify, если команда доступна в вашей версии.
  4. Шаг 4. Добавьте skill в allowlist; не давайте shell «на всякий случай».
  5. Шаг 5. Задайте агенту одну задачу: например, чеклист SEO-правок для одной money-page.
  6. Шаг 6. Уберите из workspace лишние community-skills без автора и README.

На практике precedence skills идёт от workspace /skills к ~/.openclaw/skills – см. docs по skills. Не делайте «коллекцию из десяти пакетов ClawHub за ночь»: аудит экосистемы уже ловил сотни вредоносных skills. Ориентир – один понятный skill под вашу задачу.

Соберите связку с Make на одном сценарии

Боль «агент думает красиво, а в Telegram/Sheets ничего не уходит» закрывается разделением труда. OpenClaw думает и готовит текст; Make шлёт пост, строку или уведомление. Два рабочих пути без DevOps:

Схема workflow:
Вариант A: Make (Webhook/HTTP) → OpenClaw /hooks/agent (Bearer) → ответ агента → модуль Telegram/Sheets
Вариант B: OpenClaw → MCP/plugin Make → сценарий доставки
Итог: один сценарий «отчёт агента → уведомление», без публичного gateway.

  1. Шаг 1. В Make создайте сценарий с Webhooks → Custom webhook или HTTP.
  2. Шаг 2. Подключите вызов агента (HTTP к /hooks/agent с Bearer) по гайдам интеграции; либо подключите Make-инструменты к OpenClaw через MCP/plugin.
  3. Шаг 3. Добавьте модуль доставки: Telegram, email или Google Sheets.
  4. Шаг 4. Проверьте один прогон вручную: короткий бриф → ответ → сообщение вам.
  5. Шаг 5. Сохраните сценарий и отключите лишние модули «на вырост».
  6. Шаг 6. Если нужен готовый каркас модулей – возьмите шаблон из папки блюпринтов Make.
  7. Шаг 7. Для Wordstat и картинок рядом с Cursor оставьте MCP «Всё подключено» – это отдельный слой инструментов, не замена gateway.

Часто ломается связка, когда люди открывают порт агента «для удобства Make извне». Сделайте наоборот: либо вызов с доверенного HTTP и токеном, либо MCP без публикации 18789. Избегайте ночного heartbeat «на всякий» – именно он сжигал бюджет в кейсах ~$20 overnight.

Чеклист «готово / рано / дорого»: когда OpenClaw не нужен

До FAQ зафиксируем критерий успеха: openclaw —version и gateway status зелёные; в dashboard есть ответ на тест; установлен 1 skill с известным автором; в Make есть один сценарий доставки – и gateway не торчит в интернет.

  • Готово: версия с патчем CVE, localhost, один skill, один Make-сценарий, утренний чек API без сюрприза.
  • Рано: нет ни одного стабильного сценария в Make и нет задачи «агент в мессенджере» – сначала автоматизация, потом OpenClaw.
  • Дорого: тяжёлый heartbeat, дорогая модель 24/7, десять skills без allowlist – сравните с экономикой AI-агентов в Cursor.

Сделайте паузу перед вторым агентом: чеклист выше – это ваш stop-light. Если цель – быстро собрать контент и интеграции без self-host, останьтесь на Make и Cursor. Если нужен системный разбор автоматизаций – есть курс Make.com и вайбкодинга; разборы воркеров и связок – в канале Ковчег.

Частые вопросы

Как установить OpenClaw на Windows новичку?

Откройте PowerShell и выполните официальный install.ps1 с docs.openclaw.ai/install. Проверьте openclaw —version, затем onboard и gateway status. Не публикуйте порт 18789 наружу – хватит localhost и dashboard.

Нужен ли OpenClaw, если уже есть Make?

Не всегда. Если Make закрывает доставку и интеграции – сначала доведите один сценарий до конца. OpenClaw имеет смысл, когда нужен локальный агент со skills и чатом «всегда на связи», а Make остаётся курьером.

Чем OpenClaw отличается от Cursor Cloud Agents?

OpenClaw – self-hosted gateway у вас на машине. Cursor Cloud Agents работают в экосистеме Cursor над проектом и длинными задачами. Для маркетинга часто хватает Cursor + Make; OpenClaw – отдельный слой воркера.

Какие OpenClaw skills поставить первыми (безопасно)?

Один skill с проверяемым автором: SEO+GEO или Яндекс Метрика с GitHub Horosheff. Прогоните verify, добавьте в allowlist, уберите случайные community-пакеты без README.

Сколько стоит первый месяц (API + риски overnight)?

Сам OpenClaw open-source, платите за модель (Claude/API и аналоги). Ориентир риска: heartbeat каждые 30 минут уже сжигал ~$20 overnight. Отключите лишний пульс, поставьте лимит и дешёвую модель на тесте; утром сверьте usage.

Куда класть skills и как проверить, что агент отвечает?

Skills – каталоги с SKILL.md; приоритет workspace → ~/.agents/skills → ~/.openclaw/skills. После install откройте dashboard на :18789 и отправьте тестовое сообщение – ответ в UI значит gateway жив.
