Вы вставили Webhook (вебхук) – это ссылка-розетка: сайт сам шлёт заявку на ваш URL. Вставили адрес в приёмник формы, отправили тест – и в Make пусто, в таблице тишина. Чаще всего сценарий не слушает (забыли Run once – "запустить один раз"), структура полей ещё не определена, или в ссылке затесался пробел. Пока заявки копируете руками, лиды теряются. За вечер соберём розетку: один URL принимает событие с сайта, пишет строку в Google Sheets и шлёт "новая заявка" в Telegram – без кода.

Когда webhook не нужен

Если событие редкое и вы у экрана – хватит ручного запуска. Если нет источника сигнала – не создавайте пустой хук. Типичная ошибка: сценарий без Test и без записи в Sheets. На практике Custom Webhook → один модуль → проверка payload.

Webhook (вебхук) – это ссылка-розетка: сайт сам присылает заявку, а не вы ходите за ней. В Make модуль Custom Webhook даёт уникальный URL → строка в таблице → пинг в Telegram. Это не бот заявок и не квиз: универсальный вход для формы, Tilda или тестового POST. Заявки сразу в таблице и мессенджере – меньше потерянных лидов.

В поиске по слову "webhook" часто попадаешь в Discord или Bitrix. Для заявок с сайта нужна другая картина: один Custom Webhook в Make, свой URL на сценарий (тот же адрес нельзя повесить на два сценария). Ниже – по шагам, почему тест молчит и как довести до строки плюс уведомления.

Зачем webhook маркетологу – и чем он не является

Смысл простой: заявка с лендинга сразу попадает в таблицу и мессенджер. Меньше ручного копирования, быстрее ответ человеку. Webhook url – адрес, куда форма шлёт данные; api webhook означает "сайт дернул вашу ссылку событием" (API – это запрос данных по команде, вебхук ждёт событие сам). Без такой розетки вы вечером снова открываете почту формы и вручную переносите контакты.

Граница с соседними сценариями помогает не уйти в чужой гайд:

  • Бот заявок в Telegram – человек пишет боту; здесь сайт сам шлёт POST. См. бот для заявок через Make.
  • Квиз с ветками – отдельный продукт; здесь нейтральная розетка. См. квиз лидов.
  • Нативный модуль Google Forms – удобно, если форма уже в Google. Custom Webhook нужен, когда источник любой: Tilda, свой лендинг, Postman. См. Google Forms → Make.

Ориентир на сегодня: входящий вебхук принимает событие; исходящий – вы сами стучитесь наружу. Для заявок с сайта вам нужен входящий. Webhooks telegram в выдаче часто про ботов – не путайте с входящим URL в Make.

Подготовьте лист и уведомления за 15 минут

Не делайте боевую CRM первой остановкой. На практике новичок боится "сломать таблицу" – снимите страх отдельным листом. Если тест пойдёт криво, пострадает только "Заявки_тест", а не клиентская база.

  1. Создайте Google-таблицу с листом "Заявки_тест".
  2. Добавьте колонки: дата, источник, имя, контакт, текст.
  3. Откройте аккаунт Make и новый пустой сценарий.
  4. Подготовьте Telegram-бота для пинга себе: модуль описан в apps.make.com/telegram.
  5. Держите под рукой Postman, форму или Tilda – любой источник тестового POST.
  6. Проверьте, что таблица доступна тому Google-аккаунту, которым подключите Make.

Прогресс-маркер: лист готов, бот на связи, сценарий пустой – можно ставить розетку. Шаг подготовки экономит час отладки, когда позже окажется, что колонки названы иначе, чем поля формы.

Создайте Custom Webhook и скопируйте URL

В сценарии добавьте триггер Webhooks → Custom Webhook → Add. Make покажет уникальный webhook url. Скопируйте его целиком, без пробелов в начале и в конце. Как создать вебхук без кода – ровно этот клик: модуль сам выдаёт адрес.

  1. Сделайте триггер Custom Webhook первым модулем сценария.
  2. Скопируйте URL в блокнот (не в общий чат и не в сторис).
  3. Не делайте этот же URL вторым сценарием – официально один webhook = один сценарий; для второй цепи нужен новый адрес.
  4. Если URL уже светили публично – уберите его из чатов и создайте новый webhook.
  5. Опционально позже: API key в заголовке X-Make-Apikey или IP restrictions в настройках модуля (apps.make.com/gateway).
  6. Для исходящих запросов из Make к чужим API используйте HTTP-модуль – это другой инструмент, не путайте с входящей розеткой.
  7. Официальный шаблон цепочки webhook → строка в Sheets есть в make-skills на GitHub.

Прогресс-маркер: URL у вас в блокноте, сценарий ещё выключен – рано вставлять в прод-форму. Сначала научите Make "узнавать" поля на тесте.

Как принять тест: Listening (режим ожидания), поля и типичная ошибка

Типичная ошибка из комьюнити Make: отправили POST, а полей для маппинга нет. Очередь сообщений ≠ структура данных. Нужен Run once: Listening – это режим "слушаю тест", плюс реальный payload. Без этого шаг маппинга в Sheets кликать некуда.

  1. Нажмите Run once на сценарии – модуль перейдёт в Listening (режим ожидания).
  2. Отправьте тестовый JSON, например: name, phone, message, source.
  3. Дождитесь, пока Make покажет поля (Determine / Detect data structure – "запомнить поля из теста").
  4. Проверьте, что в модуле видны имя, контакт и текст – не "unknown structure".
  5. Если поля пустые – повторите Run once и свежий POST; не мапьте вслепую.
  6. Для Tilda: отметьте сервис WEBHOOK в блоке формы, вставьте HTTPS URL Make, опубликуйте страницу; ответ должен уложиться в ~5 секунд (help Tilda). Make по умолчанию отвечает 200 Accepted – этого обычно достаточно.

Например, после удачного теста вы кликаете по полям в следующем модуле – без этого Sheets останется пустым, даже если History что-то показывает. Часто ломается связка именно здесь: человек смотрит историю, видит "Accepted" и думает, что маппинг уже готов.

Добавьте Google Sheets и Telegram – доведите до строки и пинга

Workflow: Custom Webhook → Google Sheets Add a Row → Telegram Send a Message. Модуль таблиц: apps.make.com/google-sheets. Это минимальная цепочка, которая уже спасает заявки от ручного копирования.

  1. Добавьте Google Sheets → Add a Row, выберите лист "Заявки_тест".
  2. Смапьте поля webhook на колонки дата / источник / имя / контакт / текст.
  3. Добавьте Telegram → Send a Message: "Новая заявка: {{name}}, {{phone}}".
  4. Снова Run once и тот же тестовый POST.
  5. Проверьте: новая строка в Sheets и сообщение в Telegram.
  6. Включите сценарий ON (для webhook – сразу, immediately).
  7. Избегайте публикации URL в открытых чатах после включения.
  8. Чеклист успеха: поля видны → строка есть → пинг пришёл → сценарий ON → URL не светится.

В реальном проекте этого MVP хватает на вечер: заявки уже не теряются в почте формы. Дальше можно вести сделку в CRM – см. amoCRM через Make. Пока CRM не подключена, таблица плюс пинг уже дают понятный первый результат.

Чеклист стабильности: Tilda, 200 Accepted и безопасность

Часто ломается связка "форма шлёт – Make молчит" не из-за "сломался webhook", а из-за публикации страницы, HTTP вместо HTTPS или медленного ответа. На Tilda без галочки WEBHOOK и без publish данные просто не уходят.

Риск Что сделать
Tilda ретраит заявку HTTPS URL Make, быстрый 200 Accepted, чекбокс WEBHOOK + publish
Спам на URL Не светить ссылку; IP / API key; при утечке – новый webhook
Нужен свой текст ответа Модуль Webhook Response (таймаут ответа до 180 с)
Два сценария на один URL Нельзя: сделайте второй Custom Webhook

Сделайте короткий прогон ещё раз тем же тестом: если строка и пинг на месте – круг замкнулся. Тот же POST, что утром ушёл в тишину, теперь даёт видимый результат. Это и есть критерий "готово": не теория про API, а строка в листе и сообщение в телефоне.

Если форма ещё на стадии сборки в Cursor – рядом гайд форма заявки Cursor + Make. Сравнить Make и n8n (это другой конструктор сценариев без кода): Make или n8n для маркетинга. Когда одного сценария мало и нужны агенты по хуку – Cloud Agents и Make и AI-агенты. Для Tilda-контента рядом полезен Tilda AI Agent Feeds. Готовые цепочки – в папке блюпринтов; разбор хуков и Automations – в канале Telegram Ковчег и в MAX. Системно пройти Make – курс по Make.

Частые вопросы

Чем webhook отличается от API?

API часто значит "вы сами запрашиваете данные". Webhook – событие пришло само на ваш URL. Для заявок с сайта удобнее входящий вебхук: форма дернула розетку, Make уже пишет строку.

Что такое webhook URL и куда его вставлять?

Это адрес из модуля Custom Webhook. Вставьте его в приёмник формы, Tilda (сервис WEBHOOK) или в Postman как URL для POST. Не публикуйте в открытых чатах.

Как создать вебхук в Make без кода?

Новый сценарий → Webhooks → Custom Webhook → Add → скопируйте URL. Дальше Run once, тестовый POST, Determine structure, затем Sheets и Telegram.

Можно ли принимать заявки с Tilda через webhook?

Да: HTTPS URL Make, чекбокс WEBHOOK в блоке формы, публикация страницы. Ответ уложится в лимит Tilda, если оставить стандартный 200 Accepted.

Почему после теста в Make пусто?

Проверьте Run once / Listening, свежий POST без пробела в URL и появление полей структуры. Очередь в History без Determine structure не даст маппинг в Sheets.

Чем это отличается от бота заявок в Telegram?

Бот ждёт сообщение от человека. Custom Webhook ждёт POST с сайта. Если нужен диалог в мессенджере – берите гайд про бота; если лендинг шлёт заявку – этот сценарий.

Нужен ли n8n, если есть Make webhook?

Для MVP заявок → Sheets + Telegram достаточно Make. n8n (другой конструктор сценариев) имеет смысл при других ограничениях стека – см. сравнение Make и n8n по ссылке выше.
