Ирина час копировала топ с wordstat.yandex.ru в Google Sheets, перепутала две колонки и отдала автору ТЗ с "мёртвыми" ключами. Друг сказал "подключи API" – она открыла Python-гайд и закрыла вкладку: "я не программист". Боль знакома: хочется автоматизировать частотности, но страшно сломать таблицу и непонятно, куда в Make вставить ключ. Ответ за вечер – три кубика Make и 10–20 строк phrase+count без копипаста.

Когда Wordstat API не подключать

Если хватает ручного кабинета Wordstat на 10 фраз – API избыточен. Если нет доступа к API и понимания лимитов – не ломайте сценарий. Типичная ошибка: выгрузка тысяч строк без кластера. На практике Make → Sheets → 5–15 приоритетных фраз.

Вордстат API в 2026 – это не отдельный "секретный" сервис для кодеров, а Wordstat API внутри Yandex Search API (AI Studio): вы отправляете семя фразы и получаете JSON с топом. Workflow новичка: Api-Key + folderId → HTTP POST topRequests → Iterator → Google Sheets Add a Row. Parent "вордстат" – около 108119 показов/мес, "вордстат api" – 178 (Яндекс Вордстат, регион 225, 15.07.2026). Официальная справка Яндекса уже ведёт в Search API; старый Bearer на api.wordstat.yandex.net – отдельная история, её не смешивайте с Api-Key.

Сравните сайт Вордстата и API: зачем таблица без копипаста

Боль "опять перепутал частотности" закрывается не новым скриптом, а повторяемым сценарием. Сайт wordstat.yandex.ru удобен глазами: кликнули, посмотрели, скопировали. API (application programming interface – "окошко", через которое сервис отдаёт данные по запросу) нужен, когда те же цифры должны сами лечь в лист.

На практике маркетолог с контент-планом в Sheets выигрывает на повторe: одно семя ниши → топ фраз → колонки phrase и count. Не делайте день-1 "полное семантическое ядро": сначала сырой топ, кластеры – потом. Ориентир для первого вечера – 10–20 строк, не тысяча.

Получите Api-Key и folderId в AI Studio без Python

Боль "API только для программистов" лечится двумя строками из кабинета, не курсом Python. В Cloud-пути ключ выглядит как Api-Key, а не как старый OAuth Bearer. Плюс нужен folderId – идентификатор папки в Yandex Cloud (часто виден в URL вида /folders/…). Без него API отвечает INVALID_ARGUMENT: запрос "пустой" для системы.

  1. Шаг 1. Откройте AI Studio / Yandex Cloud и создайте Api-Key для Search API.
  2. Шаг 2. Скопируйте Folder ID из URL папки – сохраните рядом с ключом в менеджере паролей.
  3. Шаг 3. Выдайте роль search-api.webSearch.user (без роли часто прилетает 403).
  4. Шаг 4. Проверьте биллинг и привязку карты: 403 бывает и из-за "нет оплаты", не только из-за опечатки.
  5. Шаг 5. Сверьте чеклист доступа в документации Wordstat MCP – те же креды пригодятся позже для агентов.
  6. Шаг 6. Уберите ключ из черновиков в Telegram и из скриншотов: только поле Connection/модуля в Make.

Типичная ошибка – смешать заголовки: Authorization: Bearer … от старых гайдов и Api-Key … от Cloud. Избегайте этого: один путь за вечер. Тарифы Search API меняются – не обещайте себе "навсегда бесплатно", просто откройте тарифы AI Studio на сегодня перед серией запросов.

Соберите сценарий Make: HTTP → Iterator → Google Sheets

Боль "куда писать Authorization и почему одна строка" закрывается тремя модулями. Make – конструктор сценариев: кубики крутятся в облаке без вашего сервера. HTTP – "курьер", который стучится в API. Iterator – "раздатчик": берёт массив results и отдаёт по одной фразе. Google Sheets Add a Row – пишет строку в лист.

Схема дня-1:
Семя ниши → HTTP POST topRequests → массив results → Iterator → Add a Row (phrase, count) → лист wordstat_raw

  1. Шаг 1. Создайте отдельный Google Sheet с заголовками phrase | count | seed | checked_at – не трогайте рабочий контент-план, заведите лист wordstat_raw.
  2. Шаг 2. В Make новый scenario: ручной триггер или Schedule.
  3. Шаг 3. Добавьте модуль HTTP Make a request: POST на searchapi.api.cloud.yandex.net/v2/wordstat/topRequests.
  4. Шаг 4. В Headers укажите Authorization: Api-Key … (ваш ключ). В теле JSON: phrase, numPhrases: 20, regions: ["225"], folderId.
  5. Шаг 5. Подключите Tools → Iterator по массиву results (не пишите весь JSON в одну ячейку).
  6. Шаг 6. Добавьте Google Sheets Add a Row: phrase и count из bundle Iterator.
  7. Шаг 7. Используйте Run once на одном семени; если mapping пустой – сначала Run this module only на HTTP, чтобы Make увидел поля ответа.

Например, в Community Make давно канон: HTTP → (при необходимости Parse JSON) → Iterator → Add a Row. В реальном проекте новички часто кладут весь ответ в одну ячейку – и думают, что "API сломан". Проверьте History: зелёный прогон и пачка bundles после Iterator – норма.

Если уже есть доступ к папке блюпринтов, можно взять готовый модуль Wordstat вместо ручного HTTP – см. папку блюпринтов Make. Для старта хватит и ручной сборки.

Проверьте первый прогон: 10–20 строк и зелёная History

Боль "в таблице одна строка вместо топа" почти всегда про забытый Iterator или пустой mapping. Сделайте прогон на одном семени ниши – том, которое уже в контент-плане. Ориентир успеха: колонки phrase и count заполнены, строк 10–20, History без 401/403/INVALID_ARGUMENT.

Часто ломается так: регион не указан, и цифры "плывут" относительно привычного кабинета. Добавьте regions: ["225"] (Россия) или осознанный город – и зафиксируйте это в заметке к сценарию. Ещё сюрприз из практики: в блоке associations частотность иногда выше "красивой" фразы из results – не пугайтесь, это связанные запросы, их можно позже брать для H1.

Между серией семян заложите паузу Sleep около 0.2–1 с, иначе легко поймать 429 (слишком частые запросы). Не делайте тысячу вызовов в первый вечер: сначала один зелёный Run once.

Чеклист ошибок и куда идти после Sheets

Боль "путаю с Метрикой API / сразу лезу в ядро" лечится границей задачи. Здесь только Wordstat topRequests. Метрика – другой API и другие ключи (см. отдельно skill Метрики). Ядрышко и Cursor – когда сырой топ уже лежит в таблице.

Чеклист перед серией семян:

  • Authorization = Api-Key (не Bearer от старого гайда).
  • folderId в теле запроса есть.
  • Роль search-api.webSearch.user и биллинг в порядке.
  • Iterator по results, не одна ячейка с JSON.
  • Ключ не в чатах и не на скринах.
  • Регион 225 или явный город.

Когда 10–20 строк стабильно появляются, перенесите частотности в контент-план – удобный соседний гайд: контент-план в Google Sheets и Make. Для кластеров откройте семантическое ядро Cursor + Wordstat. Контекст Make и агентов – в Make, AI-агентах и MCP; соседний Яндекс-модуль – IndexNow через Make. Документация MCP Wordstat и хаб MCP-KV пригодятся, когда дойдёте до Cursor.

Критерий, что вечер удался: в Sheets есть живые phrase и count; History зелёный; ключ не светится снаружи; регион осознанный. Это и есть ваш первый результат без команды разработчиков.

Если хотите системно собирать такие сценарии дальше – разбор Make с нуля есть в курсе по Make.com; для новостей стека можно заглянуть в канал @maya_pro.

Частые вопросы

Чем Wordstat API отличается от сайта wordstat.yandex.ru?

Сайт – ручной интерфейс для глаз. API отдаёт JSON, который Make раскладывает по строкам Sheets. Операторы вроде ! + [] из веба в API не гарантируют ту же "точную" частотность – ориентируйтесь на results и count как на рабочий топ для плана.

Нужен ли Cursor, если уже есть Make?

Для выгрузки частотностей за вечер – нет. Cursor и Ядрышко нужны, когда из сырого топа собираете кластеры и брифы. Сначала зелёная History и таблица, потом агенты.

Где взять ключ API Вордстата?

В AI Studio / Yandex Cloud: Api-Key + Folder ID и роль search-api.webSearch.user. Не смешивайте с legacy Bearer на api.wordstat.yandex.net. Пошаговый чеклист доступа – на mcp-kv.ru/docs/wordstat-mcp-setup.

Сколько фраз хватит новичку на старт?

10–20 на одно семя (numPhrases около 20). Не гоните тысячу фраз в первый вечер: сначала один прогон, потом серия с Sleep.

Можно ли сразу собрать семантическое ядро без Ядрышко?

Сырой топ в Sheets – да, это и есть день-1. Чистое ядро с кластерами – next-step по гайду семантическое ядро Cursor + Wordstat.

Это не путаница с API Яндекс Метрики?

Другой продукт и другие ключи. Здесь только Wordstat topRequests → Sheets. Метрику к этому сценарию не подключайте в тот же вечер.

Почему INVALID_ARGUMENT или пустой ответ?

Чаще всего нет folderId, неверная роль или смешан Authorization. Проверьте тело запроса и чеклист выше; после правки снова Run once и смотрите History.
