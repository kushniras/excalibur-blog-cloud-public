Обложки и тексты уже собираете в Make (это конструктор сценариев без кода), но перед каждым автопостом снова лезете в браузер Яндекс Диска: ищете файл и копируете ссылку руками. Время уходит не в ленту и трафик, а в ручную возню. За вечер соберите склад медиа: ключ доступа к Диску и один прогон – тестовая обложка в облаке, ссылка открывается с телефона, URL лежит в таблице для поста.

Склад контент-завода на Яндекс Диске экономит вечер перед публикацией: медиа в одном облаке РФ-стека, публичная ссылка стабильна для таблицы и автопоста. Первый шаг – ключ OAuth (это разрешение сервису работать от вашего имени) и один Run once в Make через модуль HTTP (это запросы к Диску по адресу без родного блока). После прогона файл виден в веб-Диске, ссылка открывается с телефона, URL можно отдать в соседний сценарий поста.

С 3 июня 2026 десктопный клиент Диска для Windows и macOS без подписки Яндекс 360 теряет облачную синхронизацию. Веб и программный доступ к файлам остаются рабочим путём – автоматизация через сценарий часто практичнее, чем «просто поставить программу на ПК». Важно не перепутать: яндекс диск api (это команды для файлов и ссылок) – про медиа; яндекс метрика api – про аналитику сайта. Дальше по плану: папка на Диске → токен → две HTTP-ручки → публикация ссылки → строка в Sheets.

Зачем Диск как склад до автопоста

Боль не в «облаке ради облака», а в потере минут перед каждым постом. На практике цикл «скачал → загрузил в браузер → скопировал URL» срывает ритм: обложка уже есть, а в Telegram или VK всё ещё нечего вставить. Стабильный адрес файла в облаке быстрее доводит контент до ленты и кликов.

Google Drive в части сценариев тоже умеет хранить файлы, но для РФ-стека Диск чаще оказывается привычнее команде: один аккаунт Яндекса, веб без лишней возни и ссылка вида yadi.sk, которую автопост забирает из таблицы. Не обещаем «магию трафика» – обещаем меньше ручной возни до публикации.

Ориентир на вечер: один тестовый файл, не «идеальная архитектура». Если обложку ещё генерируете руками, сначала загляните в гайд обложка для поста нейросетью – сюда приходите, когда картинка уже готова и нужен склад.

Прогресс: поняли, зачем ссылка до автопоста – дальше готовим папку и ключ.

Подготовьте папку и ключ доступа за 15 минут

Типичная ошибка – регистрировать приложение «на глаз» и потом искать, куда делся токен. Сделайте короткий чеклист до Make:

  1. шаг 1: создайте на Диске папку вроде /content-factory/covers/ и положите одну тестовую картинку.
  2. шаг 2: зарегистрируйте приложение на oauth.yandex.ru; Redirect URI – https://oauth.yandex.ru/verification_code.
  3. шаг 3: выдайте права cloud_api:disk.read и cloud_api:disk.write (при необходимости app_folder и info) – это scopes, набор разрешений приложения.
  4. шаг 4: откройте ссылку authorize с response_type=token и client_id; скопируйте access_token из адресной строки после #.
  5. шаг 5: сохраните токен у себя в менеджере паролей; не делайте вставку токена в чат «на всякий случай».
  6. шаг 6: добавьте в Google Sheets колонку URL – туда позже ляжет публичная ссылка.

Яндекс не показывает выданные токены в кабинете повторно: не успели скопировать – придётся выписать новый. Официальная справка по ручному токену: debug-token. Прогресс: токен сохранён локально, папка готова.

Соберите загрузку в Make: GET, PUT и publish

Родного модуля Диска в аккаунте может не быть – это нормально. Используйте модуль HTTP: Make a request. Workflow (порядок шагов) – это короткая цепочка из двух-трёх запросов, а не «выучить весь REST».

  1. шаг 1: GET на https://cloud-api.yandex.net/v1/disk/resources/upload?path=disk:/content-factory/covers/test.jpg с заголовком Authorization: OAuth … (не Bearer).
  2. шаг 2: из ответа возьмите href – это адрес загрузки примерно на 30 минут.
  3. шаг 3: PUT бинарника файла на этот href; на этом шаге токен в заголовке не нужен.
  4. шаг 4: при успехе ждите HTTP 201; файл должен появиться в веб-Диске.
  5. шаг 5: PUT publish на ресурс – в ответе появится public_url вида https://yadi.sk/…
  6. шаг 6: запишите URL в Sheets; по желанию уведомите себя через Telegram в Make.
  7. шаг 7: если картинка уже лежит по внешней ссылке нейросети – вместо локального PUT используйте POST upload-ext с url и path (ответ 202).

Контраст, который часто ломает новичка: не шлите JSON «в теле вместо query» и не подменяйте канон GET→href→PUT одним POST с Bearer. Документация Яндекса: upload и publish. Для долгой OAuth-связки в Make смотрите живой гайд OAuth 2.0 на HTTP. Если сценарий Make ещё не собирали ни разу, начните с первого сценария: webhook (ссылка-розетка для входящего события) – это удобный вход, чтобы привыкнуть к кнопке Run once (один тестовый запуск).

На практике удобно сначала прогнать загрузку на маленьком JPG, а уже потом подставлять путь к боевой обложке. Так вы не ждёте 30 минут истечения href из-за правки опечатки в path. Прогресс: после одного Run once файл виден в папке Диска.

Чеклист ошибок: 409, Bearer и чужой API

В реальном проекте чаще всего ломается не «магия облака», а мелкий заголовок или путь. Пройдите чеклист до того, как чинить всё подряд:

  • избегайте заголовка Authorization: Bearer – для Диска нужен OAuth.
  • уберите лишний пробел в токене и кавычки вокруг значения.
  • при 409 файл уже есть: либо другое имя, либо overwrite=true осознанно.
  • 413 / 507 – слишком большой файл или место на Диске кончилось; уменьшите тест.
  • путь с двоеточием: используйте префикс disk:/…; схема app:/ – другая папка приложения, её легко перепутать (это частая боль в community-клиентах Disk).
  • не делайте приложение Метрики «вместо Диска» – разные кабинеты и разные права.
  • если href протух – сделайте новый GET upload; старый адрес загрузки после 30 минут не оживляйте.

Часто ломается и «тихий» сценарий: модуль зелёный, а в веб-Диске пусто – проверьте path и имя файла в query, а не только код ответа. Прогресс: знаете, что править, если History в Make красный.

Проверьте результат и отдайте ссылку в автопост

Готово, когда одновременно три вещи: файл виден в веб-интерфейсе Диска, public_url открывается с телефона без логина владельца, URL записан в Sheets (или хотя бы в заметку). Тогда соседний сценарий автопоста получает стабильный адрес, а не «файл у меня на ПК».

  1. Нажмите Run once и проверьте History: зелёные модули HTTP.
  2. Откройте папку covers в браузере Диска – тестовый файл на месте.
  3. Откройте public_url с телефона в режиме инкогнито.
  4. Проверьте строку в Sheets: URL не обрезан.
  5. Дальше подключите автопост – Telegram и VK без кода или цепочку нейросеть → пост.
  6. Сравнение стека, если выбираете инструмент: Make или n8n (это альтернативный конструктор сценариев) для маркетинга.

Круг закрыт: вместо вечерней петли «браузер Диска → копировать ссылку» у вас склад медиа и готовый URL. Модули Диска для пирожочков обсуждали в канале пост #1086; готовые сценарии – в папке блюпринтов. Разбор шагов и разборы ошибок – в Telegram Ковчег и в MAX; системно пройти Make – на курсе.

Частые вопросы

Чем яндекс диск api отличается от яндекс метрика api?

Диск – про файлы, папки и публичные ссылки для медиа. Метрика – про счётчики и отчёты сайта. Регистрируйте приложение под нужный продукт, иначе токен «не туда» и права не подойдут.

Как получить токен для api яндекс диск самостоятельно?

Сделайте приложение с Redirect URI verification_code, откройте authorize?response_type=token, скопируйте access_token из hash. Код писать не нужно – достаточно браузера и сохранённого ключа.

Подойдёт ли связка Диска и Make маркетологу без кода?

Да: модуль HTTP и два-три запроса по документации Яндекса. Ориентир успеха – файл в веб-Диске и ссылка с телефона после одного Run once.

Можно ли загрузить файл на Диск через Make без родного модуля?

Да. Используйте apps.make.com/http: GET upload → PUT файла на href (или POST upload-ext, если файл уже по URL).

Куда положить public_url перед автопостингом в Telegram и VK?

Сначала в Google Sheets или заметку, затем в сценарий автопоста. Так ссылка не теряется между прогонами и её видно команде.

Что делать при ошибках загрузки 409, 413 или 507?

409 – конфликт имени: смените path или включите overwrite осознанно. 413 – уменьшите файл. 507 – освободите место на Диске и повторите GET за новым href.

Нужен ли десктопный клиент Диска после июня 2026, если есть сценарий?

Для контент-завода достаточно веба и API/Make. ПК-клиент без подписки 360 с 3 июня 2026 теряет облачный синк – на склад медиа через HTTP это не мешает.
