Оля ведёт лендинг и Директ: счётчик уже стоит, а каждое утро снова открывает кабинет Метрики, кликает пресеты и забывает, что смотрела вчера. Боль знакома – "яндекс метрика api" в поиске ведёт в курсы Python и Logs API, и кажется, что без программиста не обойтись. Ответ за один вечер: skill в Cursor, OAuth с правом чтения статистики и вопрос "покажи визиты за 7 дней" – цифры в чате без кода.

Когда Метрику API не трогать

Если счётчика ещё нет на сайте – сначала установка тега. Если нужен один отчёт в кабинете – API и skill лишние. Типичная ошибка: токен в чат и утечка. На практике Secret → skill → один отчёт без паролей в промпте.

API Метрики – это не "ещё один код на сайт", а способ спросить отчёты программно. Новичку нужен Reporting API (чтение готовых сводок), а не Logs API с сырыми хитами. Workflow: счётчик уже копит данные → skill → токен metrika:read → "список счётчиков" → "визиты за 7 дней". Parent "яндекс метрика" – около 112521 показов/мес, primary "яндекс метрика api" – 356 (Яндекс Вордстат, Россия, 14.07.2026). Квота отчётов жёсткая: до 200 запросов к /stat/v1/data за 5 минут – иначе 429.

Разведите счётчик на сайте и API отчётов

Типичная ошибка – гуглить "яндекс метрика api" и сразу лезть в head страницы или в tag.js. Это другая задача. Счётчик собирает визиты; API (Application Programming Interface – "окно", через которое программа просит данные у сервиса) отдаёт уже собранные отчёты. На практике Оле не нужен новый код на лендинг: ей нужен доступ "прочитать статистику".

Сделайте паузу и проверьте: в кабинете Метрики есть счётчик, цифры за вчера не пустые. Не делайте из этой статьи установку счётчика – иначе потеряете вечер. Ориентир простой: данные уже есть → идём в OAuth и skill.

Сравнение: кабинет, Python+Logs и skill в Cursor

Боль "API = писать Python / ClickHouse" закрывается выбором пути, а не мотивацией. Reporting API – это готовые таблицы (визиты, источники, страницы). Logs API – сырые хиты для своей базы: для первого отчёта маркетологу почти никогда не нужен.

Путь Что получите Сложность для новичка Когда брать
Кабинет Метрики Клики по пресетам Низкая, но легко забыть вчерашний срез Разовый взгляд "здесь и сейчас"
Python + Logs API Сырые данные, своя БД Высокая Аналитик с пайплайном выгрузки
Skill в Cursor / OpenClaw Отчёт по фразе на русском Низкая за вечер Ежедневный вопрос "откуда трафик"
MCP-серверы Метрики Инструменты в чате Claude/Cursor Средняя (env, npx) Когда уже освоен MCP

Вердикт: для первого вечера используйте skill и Reporting API. Избегайте Logs API и курсов "под ClickHouse", пока не умеете читать один отчёт визитов в чате. Про MCP как розетку для инструментов – в подключении MCP в Cursor; про агента у себя – в установке OpenClaw.

Важный нюанс из официального Reporting API: в одном запросе нельзя смешивать префиксы ym:s: (визиты) и ym:pv: (просмотры страниц). На практике это типичная 400 у новичков и у агентов без skill, которые "угадывают" метрики сами.

Получите OAuth-токен с правом metrika:read

OAuth здесь – это "пропуск" Яндекса: вы создаёте приложение и один раз разрешаете читать статистику. Scope (галочка прав) для отчётов – metrika:read: получение статистики, чтение параметров и список счётчиков. Write нужен только если агент будет менять цели или настройки счётчика – в первый вечер его не включайте без нужды.

  1. Шаг 1. Откройте oauth.yandex.ru и создайте приложение "для API / отладки".
  2. Шаг 2. В Redirect URI укажите https://oauth.yandex.ru/verification_code – как в INSTALL-FOR-HUMANS-RU.
  3. Шаг 3. Отметьте галочку чтения статистики (metrika:read); сохраните Client ID.
  4. Шаг 4. Откройте ссылку authorize с response_type=token и своим client_id.
  5. Шаг 5. Скопируйте access_token из фрагмента URL после # – это и есть получить api яндекс метрики на практике.
  6. Шаг 6. Сохраните токен в переменную YANDEX_METRIKA_OAUTH_TOKEN или в поле oauthToken плагина; опционально добавьте defaultCounterId.

Не делайте скрин токена в публичный чат и не коммитьте его в git. Уберите токен из истории переписки, если уже вставили "на всякий случай". Без токена или с битым – HTTP 401; без нужного scope – 403. Официальная шпаргалка прав: документация Authorization.

Поставьте skill в Cursor или через ClawHub

Skill – это папка с файлом SKILL.md: инструкция для агента "как ходить в Метрику". Cursor подхватывает skills из .cursor/skills/ (см. документацию Cursor Skills). Канон канала – репозиторий Horosheff/yandex-metrika-assistant (MIT, зеркало на ClawHub).

  1. Шаг 1. Склонируйте репозиторий или скопируйте папку в .cursor/skills/yandex-metrika-assistant/.
  2. Шаг 2. Для OpenClaw: openclaw skills install yandex-metrika-assistant с ClawHub – если gateway уже стоит.
  3. Шаг 3. Проверьте, что в чате Agent skill виден (агент ссылается на инструкции Метрики).
  4. Шаг 4. Убедитесь, что токен лежит в env/конфиге, а не в тексте промпта.
  5. Шаг 5. Спросите: "Покажи список моих счётчиков Метрики" – живой OAuth даст список, не отказ.
  6. Шаг 6. Если агент молчит про skill – перезапустите чат Agent и проверьте путь папки.
  7. Шаг 7. Не ставьте сразу три MCP Метрики "на всякий случай": один skill проще отладить.

В реальном проекте хватает одного пакета. Если Cursor ещё непривычен – сначала вайбкодинг маркетинга в Cursor, затем вернитесь к Метрике. Для длинных задач в облаке смотрите Cursor Cloud Agents.

Запросите первый отчёт: визиты за 7 дней

После списка счётчиков сделайте один отчёт – не "проверь всё". Reporting API отвечает на GET /stat/v1/data: агент спрашивает метрики и группировки, вы видите таблицу или markdown в чате. Например: "Визиты по дням за последние 7 дней", затем "источники трафика" и "топ страниц". Цели в яндекс метрике – следующий слой, когда визиты уже совпали с кабинетом.

Проверьте цифры глазами в личном кабинете Метрики за тот же период. Если расхождение огромное – чаще всего неверный counter id, а не "сломанный API". Используйте одну фразу за раз: спам отчётов упирается в квоту 200 запросов за 5 минут (и лимиты 30 rps / 3 параллельных / 5000 в сутки по квотам API).

Часто ломается сценарий, когда агент без skill сам собирает URL и мешает namespaces – skill как раз держит "маршрут" запросов. Анализ данных яндекс метрики на старте – это не дашборд в DataLens, а короткий ответ агента, который можно сохранить в файл проекта. Не делайте массовый обход всех пресетов в первый вечер: сначала один ясный срез "вчера vs 7 дней".

Чеклист вечера: токен, квоты и критерий успеха

Ниже – чеклист stop-light перед тем, как звать Logs API или SEO-аудит.

  • Счётчик на сайте уже копит данные (иначе – sibling про установку).
  • Токен metrika:read в env/плагине, не в git и не в публичном чате.
  • Агент показал список счётчиков.
  • Отчёт визитов за 7 дней совпал по порядку величины с кабинетом.
  • Не смешивали ym:s: и ym:pv: в одном запросе.
  • Не упёрлись в 429: 1–2 отчёта, пауза при ошибке.
  • Следующий слой: цели или SEO-аудит skill по money-page – не Logs "потому что модно".

Критерий успеха: агент ответил списком счётчиков или таблицей визитов/источников за выбранный период; токен не светится в истории чата и не лежит в репозитории; вы понимаете, что это Reporting API (чтение отчётов), а не код счётчика в head и не Logs API. Сделайте паузу на этом результате – этого достаточно на сегодня.

Частые вопросы

Чем яндекс метрика api отличается от кабинета?

Кабинет – клики руками. API – программный запрос отчётов. Сделайте skill и спросите визиты текстом; кабинет оставьте для сверки цифр.

Нужен ли OAuth или хватит номера счётчика?

Номера счётчика мало: без OAuth-токена API ответит 401. Проверьте, что токен с metrika:read лежит в env, а counter id – отдельно.

Можно ли тот же skill через OpenClaw?

Да: поставьте пакет с ClawHub (yandex-metrika-assistant) и используйте тот же токен. Сначала живой gateway – см. гайд по установке OpenClaw.

С какого отчёта начать новичку?

Список счётчиков → визиты по дням за 7 дней → источники. Избегайте Logs API и целей, пока визиты не совпали с кабинетом.

Как не слить токен в git?

Уберите токен из файлов проекта: только секрет окружения или поле плагина. Не делайте commit с .env и не вставляйте токен в чат.

Зачем вообще logs api яндекс метрики?

Для выгрузки сырых хитов в свою систему. Для ежедневного "откуда трафик" используйте Reporting API через skill – Logs отложите.
